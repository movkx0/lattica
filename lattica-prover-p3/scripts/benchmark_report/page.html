Apple Silicon optimization results

Audited recursive proofs

Horizontal bars show recursive command time; shorter is faster. Single observations show the recorded time. Repeated configurations show the median and a dark minimum-to-maximum range. Every sample is a fresh eight-wallet aggregation with seven recursive proofs and a separate CPU root audit.

What each optimization changes

Parallel readback changes host decoding. Fusion combines quotient work. GPU quotient adds device quotient-LDE operations. Compact data retains a smaller prover representation and reconstructs needed openings. Deferred timing reads GPU timestamps in bounded batches at fences and checkpoints. The experiments preserve proof parameters and require exact CPU verification.

Matched shared/copy comparison

Elapsed-time differences include all work in the recursive commands. GPU, blit and host-copy counters overlap; none is a separate additive explanation of the wall-time difference.

All samples, observed memory and evidence

Shared and copy modes run on the same unified-memory Mac. Their difference measures the benefit of avoiding explicit transfers under this workload. Linux comparisons also differ in hardware, kernels and revision; they do not isolate memory architecture. RAM, mapped data, GPU buffers and process RSS overlap and must not be added. Wallet creation, networking and chain acceptance are outside this research benchmark.

SME2 integer arithmetic experiment

Component only

Exact Goldilocks multiplication, one CPU thread. These timings compare streaming SVE through SME2 with Plonky3's existing ARM packing and the scalar u128 correctness oracle. They are not proof throughput or an enabled prover backend.

Bars are medians in nanoseconds per field multiplication. All seven samples are retained. C ABI calls and streaming-mode transitions are timed; allocation, conversion and verification are excluded.
