GPU recursive aggregation

7 November 2026 · base dc5a782 · isolated gpu-recursive-aggregation branch · Linux OpenCL / RTX 5080

Research implementation; complete N3/N4 latency is not qualified. The new path aggregates verified native component proofs. Transaction generation and native component preparation are separate operations. All preparation and validation attempts count against the campaign's cumulative 3,600-second testing allowance; builds are excluded. No individual hardware attempt may exceed 600 seconds.

Implementation

  • One GPU consumer overlaps preparation with two CPU workers. Four permits cover compilation, queued programs, identity prefixes, and GPU consumption together. Ordered consumption, odd tails, cancellation, and panic cleanup preserve coverage.
  • CPU identity hashing runs in the preparation worker without acquiring a GPU session. Optional GPU identity batches contain at most four programs and remain bound to the same live device epoch. Prefixes are consumed once by the exact registered program.
  • The opt-in fused witness kernel runs up to 32 consecutive narrow waves in one workgroup. Wide waves retain their existing dispatch. Every lane reaches each global-memory barrier, including inactive and failing lanes.
  • An engine-local eight-entry LRU reuses specialized OpenCL programs, including negative specialization results. Its key covers exact source and compiler options; the owning engine fixes device/context. Eviction drains queued work. It retains no witnesses, challenges, or mutable proof buffers.
  • SHAKE groups of up to eight native verifiers preserve every original boundary. Geometry preflight freezes groups before proving. Graph grouping uses measured costs and a contiguous dynamic-programming partition; it retains singleton leaves when larger groups exceed bounds or lack a measured gain.
  • Coordinator and worker metadata caches avoid repeated descriptor compilation. Cache keys remain source-bound. An incompatible precomputed table falls back to dynamic planning.

Resource and verification contract

The driver is isolated behind gpu-aggregation-experiment. Legacy APIs keep their prior admission behavior. The imported path uses the existing owned GPU registration and PCS phase checks instead of treating the full CPU LDE representation as GPU host storage. Source construction is bounded, rows are capped at 218 (262,144), and registration/proving retain separate host and managed-device limits. The external guard pins the physical GPU, enforces exclusive hardware use, disables swap, and retains the existing N3/N4 process caps.

The driver's resource ledger represents conservative reservations, not measured RSS or a complete allocation-derived proof of memory bounds. Opaque OpenCL driver storage is covered by the existing driver reserve and context checks. macOS and CUDA execution have not been qualified by this campaign.

Input bundles bind public inputs, source identity, file lengths, and digests. Native artifacts are independently verified against the current trusted graph; missing inputs never trigger native proving during aggregation. Recursive proofs are always fresh. Complete acceptance additionally requires final CPU verification, artifact serialization/reverification, altered public/proof rejection, and missing/reordered statement rejection. Screens cannot qualify a complete aggregate.

Validation

Focused checks passed: 21 research tests, six core unit tests, three GPU correctness tests, and 46 Python guard/controller tests. GPU checks cover fused-witness parity including wide-wave boundaries, specialized-program/context cache reuse, and CPU/GPU identity-prefix parity and epoch rejection. Those core GPU implementation files were unchanged after testing. The existing OpenCL full-workflow and CPU-proof feature configurations also compile.

The full-artifact acceptance checks described above are implemented but have not been exercised on a complete N3/N4 artifact in this campaign. Scheduling currently proceeds level by level. Resource reservations are not a complete allocation-derived memory bound. The evidence ledger includes all failed and manually stopped attempts.

Reproduction

The controller research/pq-ringct/tools/gpu_aggregation_campaign.py provides separate build, tests, GPU tests, Python tests, driver, and summary commands. Use a unique revision and job label for each attempt. The persistent budget ledger must not be reset to extend a campaign.

python3 research/pq-ringct/tools/gpu_aggregation_campaign.py build --kind runner --revision NEW
python3 research/pq-ringct/tools/gpu_aggregation_campaign.py driver \
  --revision NEW --label shake-baseline --command screen --case n4 \
  --bundle /absolute/native-bundle --device-uuid GPU-... -- \
  --profile legacy --group-width 2 --pipeline serial --request 6 --repetitions 4
python3 research/pq-ringct/tools/gpu_aggregation_campaign.py driver \
  --revision NEW --label shake-candidate --command screen --case n4 \
  --bundle /absolute/native-bundle --device-uuid GPU-... -- \
  --profile grouped-v2 --group-width 2 --pipeline lookahead \
  --identity cpu --request 6 --repetitions 4

Run prepare-inputs separately to populate a bundle from its public inputs.json. A request-filtered or graph-screen bundle is explicitly incomplete. Graph screens use --screen-family graph --first-leaf 4 --leaves 8. GPU identity comparison uses --identity gpu-batched; batches of eight or sixteen are not admitted by the four-job queue.

gpu_aggregation_select.py --pair BASELINE_RECORD CANDIDATE_RECORD --output SELECTION requires matching source, device, input, and subtree scope, plus one first request and three warm requests. Only widths with at least a 10% median gain are eligible. A run needs a complete native bundle, a new output artifact path, and, for grouped-v2, a measured selection file. Qualification requires three distinct successful full artifacts for both N3 and N4 with consistent source, executable, device, settings, selection, and per-case inputs.

Measurements, provenance hashes, selected costs, failures, and the cumulative budget ledger are preserved in the evidence JSON. Raw records and logs remain in .tools/pq-opencl-opt/runs/gpu-agg-* in this worktree.
