Constraint and compatibility checks

Hash degree increases from 4 to 8 and hash quotient chunks from 8 to 16. The pinned blowup, challenge parameters, fresh randomness, and total quotient-matrix limit are unchanged. The planner explicitly rejects layouts that exceed the existing verifier capacity.

23 core/PCS tests, 39 workflow tests, and 73 Python tests passed. CPU-only compilation passed. GPU samples verify, with tamper checks, source-integrity receipts, and drained sessions. The complete five-segment AES request also passes. A regression test requires the hash quotient to fit the existing GPU specialization envelope.

The four-lane prototype reduced data further but lost the specialized hash kernel and regressed runtime on graph, parent, and SHAKE screens. Its receipts are preserved in the evidence; it is not the final implementation.

Evidence and limits

Full timings, geometry, stage observations, commands, and receipt hashes · Previous completed pass

  • No complete fresh N3/N4 workflow was timed. All screens revalidate archived native proofs and produce fresh recursive proofs; native transaction proof generation is excluded.
  • Graph timing covers eight GBound native leaves at offsets 4..11 of transaction 0. Parent timing covers eight singleton groups, two four-child parents, and a two-child root.
  • SHAKE timing is GPU proof execution only for the first 16 segments of request 1, which has 109 segments. Warm medians use two current samples; the r90 baseline has one warm sample.
  • The AES screen covers the complete five-segment request 4. It qualifies the new layout but is not used to claim an improvement over r90, which did not measure this request.
  • First-use and warm samples are separate. Kernel and driver cache state is not controlled, and parent timing has one sample per revision.
  • The first graph sample took 46.916 seconds versus 20.216 in r90, including a measured 30.563-second build of the new specialized hash kernel. This initial compilation cost is not part of the warm comparison.
  • SHAKE warm GPU proof time increased by 0.9%, from 15.513 to 15.650 seconds. No SHAKE speedup is established; the measured parent hierarchy is the main completion-time improvement.
  • Stage device durations and inclusive host spans overlap; they are not additive elapsed-time breakdowns.
  • These Linux OpenCL checks do not qualify a complete RingCT aggregate, macOS, or CUDA.
