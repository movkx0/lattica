Move hash inputs into the hash proof

The default recursive prover folds sibling ordering and private input providers into the existing hash table. It removes intermediate circuit rows while preserving the lookup constraints that bind shared values.

What changed

  • Fuse complete, single-consumer Merkle sibling swaps into the existing Poseidon table, preserving authenticated direction bits and all hash constraints.
  • Relocate private Input providers into their first hash use. Trusted signed lookup counts bind every other use, including arithmetic before the provider and other hashes; public values, constrained computations and execution hints keep their original providers.
  • Use one shared hash table for ordinary and fused hashes, preserving the eight-table / 64 quotient-matrix limit and bounded host/GPU admission.
  • Version the recursion template and record geometry, operation elimination and provider multiplicity bounds in every GPU proof measurement.

Validation

16 core tests and 39 workflow tests passed; 73 Python tests passed; CPU-only compilation passed. Four GPU screens independently verified their fresh proofs. The new adversarial test changes a provider while retaining valid local computations, and confirms that the global lookup rejects the inconsistent shared value.

Scope and limits

  • These are bounded component/subtree measurements, not a full N3/N4 aggregate or transaction-generation run. The planned N4 proof count remains 131, excluding auxiliary branches.
  • The graph comparison uses the immediately preceding r86 typed default committed in b46423b. AES and SHAKE references are the earlier qualified r83 and r75 profiles. Source versions differ deliberately; all runs use the same deterministic N4 inputs and revalidated archived native proofs.
  • Warm medians use samples 2 and 3. First-use measurements and public setup times are retained separately. The first GPU proof can be substantially slower than warm proofs; warm speedups are not full-workflow predictions.
  • Graph and AES elapsed times include native archive reimport/verification, circuit compilation, fresh recursive proof generation and CPU verification. The SHAKE comparison measures GPU proof execution only; compilation and public setup are separate.
  • The graph parent screen uses eight singleton native groups, two four-child parents and one two-child root. It does not cover every heterogeneous graph geometry.
  • All hardware checks retain the 10.5 GiB managed GPU allowance and 36 GiB worker envelope, use one GPU consumer, and keep security parameters, native proof semantics and the final aggregate format unchanged.
