GPU aggregation defaults

November 9, 2026. The measured implementation now replaces the previous default path at the user's request. The 10% promotion gate no longer prevents use of the new defaults.

  • Ordinary OpenCL GPU builds use the smaller NTT tiles and cached twiddle powers for the admitted NVIDIA shapes. This no longer requires gpu-tuning or an environment flag. Other devices and shapes retain the existing compatible kernels.
  • The aggregation command defaults to four-wide consuming aggregation, CPU identity hashing, lookahead preparation, batched queries and the standard compiler/window policy.
  • The automatic GPU memory budget uses up to 10.5 GiB, constrained by current free VRAM, the context reserve and headroom. Explicit research budgets up to 12 GiB remain available. An unqualified build retains its 4 GiB context reserve.
  • Full aggregation can run without a measured-selection file. Such files remain optional cost hints; source, geometry, memory admission and proof verification still apply. Historical profiles remain explicit benchmark controls.

The guarded runner accepts screen --case n4 --input-bundle PATH or run --case n4 --input-bundle PATH --output NEW_ABSOLUTE_PATH with no optimization-selection flags. Physical GPU pinning and the existing execution guard are still required.

Validation

The ordinary GPU library, aggregation library/binary and CPU-only configuration built successfully. Focused core, pipeline, controller and memory tests passed. A GPU test built without gpu-tuning exercised the default NTT on a 2¹⁸-row LDE and matched an independent CPU reference. Bare graph and SHAKE commands generated and verified 8 recursive proofs and closed both sessions. These were bounded N4 subtree checks; full-workflow timing remains unqualified.

The prior matched benchmarks measured graph improvement from 53.07 to 50.34 seconds and SHAKE improvement from 71.81 to 68.55 seconds. Those historical results used the same selected kernel and managed-memory budget with a separately qualified 2 GiB context reserve. This change validates default routing and correctness; it does not claim a new warm benchmark. Old qualification files remain bound to their original source and executable.
