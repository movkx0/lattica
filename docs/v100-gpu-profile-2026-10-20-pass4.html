V100 prover: external matrix reduction and fixed-stage bit reversal

20 October 2026 · Fourth optimization pass · Tesla V100-PCIE-32GB

This run compares the previous scalar_limb release with external_brev. Both use fresh proofs, the same fixtures and the same independent CPU verifier binaries. Earlier campaign evidence remains intact.

The selected change lowers median latency by 3.60% for four-input aggregation, 3.21% for eight-input aggregation, and 3.33% for two concurrent eight-input jobs; all seven aggregation pairs favor the candidate. Native JoinSplit has a 1.23% lower pooled median and seven wins in twelve pairs, but paired changes range from a 5.53% regression to a 6.31% improvement. This run does not establish a stable native latency gain. All 60 benchmark outputs passed independent CPU verification.

Changes and arithmetic bounds

The Poseidon2 external matrix now accumulates each input's low and high 32-bit limbs with ordinary integer additions. Each output's coefficients sum to 21, so each limb sum is at most 21 × (2³² − 1), below 2³⁷. Reconstructing the exact sum produces a high 64-bit word of at most 20. One Goldilocks fold and one carry correction therefore suffice. This replaces modular reduction after each intermediate addition with one reduction per output.

Bit reversal now uses five fixed stages of unsigned masks and shifts, followed by truncation to the public row-index width. The zero-bit case avoids a shift by 32. The implementation uses portable OpenCL operations.

The screening harness independently checks complete permutations and NTTs, including direct DFT sums for small shapes.

The benchmark ledger contains 60 independently CPU-audited outputs representing 192 fresh benchmark proofs. Output hashes are unique, every required GPU stage is covered, and native public-input tampering is rejected. All 690 selected source-file hashes match release and test builds.

Other candidates screened

  • M4-only limb accumulation: mixed/slower kernel timings
  • generic external limb reduction: smaller improvements than the bounded exact reduction

Timer boundaries

  • Four-input aggregation: Aggregation call plus GPU drain; excludes context initialization, artifact output and CPU audit.
  • Eight-input aggregation: Cohort launch to worker exit; includes initialization, start barrier, aggregation, artifact output and shutdown; excludes CPU audit.
  • Two concurrent eight-input jobs: Cohort launch to last of two worker exits; includes both initializations, start barrier, aggregations, artifact output and shutdown; excludes CPU audits.
  • Native JoinSplit: Native ABI proving call plus GPU drain; excludes context initialization, buffer setup, artifact output and CPU audit.

Research used

  • NVIDIA CUDA C++ Best Practices Guide: Guided instruction-count reduction and paired measurement. Arithmetic bounds were derived and tested independently.
  • NVIDIA Volta Tuning Guide: Guided evaluation of dependency chains and register-resource tradeoffs. Performance decisions use measurements on this device.

Scope and limits

  • One Tesla V100-PCIE-32GB, fixed aggregation fixtures and bounded resource settings.
  • Three four-input pairs, two eight-input pairs, two concurrent pairs and twelve native pairs; limited sample counts.
  • Warmed alternating pairs. First-use profiles and warmups are retained but excluded from the qualification medians.
  • Both pooled medians and within-pair reductions are reported; short native calls remain sensitive to timing variation.
  • Kernel event totals and inclusive host spans are not additive; gaps in event coverage do not establish GPU idle time.
  • No cold-cache, Apple GPU, full-block or production qualification in this run.
