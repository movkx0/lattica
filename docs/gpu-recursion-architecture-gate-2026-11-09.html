Recursive aggregation: architectural prototype and gate

Full implementation remains incomplete. The performance gate is not qualified. The prototype reduces committed table work, but opens substantially wider rows. The current GPU aggregation backend remains the default. No N3/N4 latency or 2× GPU speedup has been demonstrated.

The final prototype separates arithmetic, cubic-extension, Poseidon2, and public bindings. Its complete symbolic constraints have degree at most four and use eight quotient chunks, including lookup constraints and the existing zero-knowledge profile. The compared legacy wrappers use sixteen chunks. RingCT native contracts and security parameters were not changed.

These are geometry measurements of actual compiled native verifiers. Logical LDE payload sums field values across all committed matrices and domains; it is not peak VRAM. The opening-width proxy sums committed columns without height weighting because queries open rows from every committed matrix. It is not a measured proof-size or parent-runtime ratio. Recursive parents and transaction seals are outside these screens.

The first layout increased logical LDE work by about 42% on four-proof groups. Sharing opcode selectors and using a single cubic s-box witness reduced that penalty. The key final change splits a table into a full prefix and a short tail when that saves padded rows: the graph hash table has 262,594 active rows, represented by domains of 262,144 and 512 rows instead of 524,288 rows. Global wire lookups preserve all cross-table links.

Implemented and tested:

  • Trusted-program and registry-bound immutable templates with separate witnesses.
  • Reusable bounded CPU preparation with deterministic public preprocessing and fresh per-proof randomness.
  • Arithmetic, cubic-extension, Poseidon2, and public-binding AIRs with a global authenticated wire bus.
  • At most two exact contiguous spans per table kind; small tails avoid a full extra power-of-two domain.
  • Actual graph and SHAKE wrapper geometry screens, including the 109-component request.
  • Explicit bounded archive revalidation against current native contracts, without rewriting files or creating current cache entries.

Validation passed: 5 core tests, 20 research tests, and 62 controller tests (87 total). One existing GPU-only research test remained ignored. Four fresh CPU execution proofs exercise the new AIRs, preparation reuse, changed witnesses, registry rejection, and split-table verification. They are bounded correctness proofs, not full RingCT recursive aggregates. Core, research, runner, and CPU-only builds passed.

The final SHAKE screens independently reverified 119 archived native proofs against current request contracts. Stored source information remained explicitly untrusted metadata. No archive file was rewritten, no current cache entry was created, and all GPU sessions closed.

Work still required before promotion:

  • Proof-indexed shared verifier bodies and witness schemas replacing repeated compiler emission in the live workflow.
  • Recursive verification of the new multi-table proof, authenticated key-registry membership, and bounded opening costs.
  • 16-child native batches, eight-way reductions, fused transaction checks, and AggregateArtifactV2 codec/verifier.
  • Reusable GPU preparation, persistent device data, global dependency scheduling, and measured memory admission.
  • Matched GPU subtree timing and three fully verified N3 plus three N4 runs within the latency targets.

The next architectural prototype must reduce the recursive verifier's opening cost and share verifier logic across proof witnesses. Porting this layout alone would not establish the requested end-to-end improvement.
