Architecture and planning

  • Typed request proofs bind exact request descriptor, index, context, statement, endpoints and complete coverage in existing graph consumers.
  • One weighted CPU preparation queue spans SHAKE requests and transactions, with up to 16 workers and one GPU owner. Native and symbolic preparation reservations are included.
  • GPU proving state retains compact AIR descriptors; compiler source is retired before private GPU work, releasing the weighted permit for another preparation job.
  • One exact-identity public preprocessing cache occupies the existing backend allowance. A miss evicts before replacement; no compiler programs, witnesses or private randomizers are cached.
  • Matching request positions are adjacent across transactions, and parent reductions follow request order, to improve exact-template reuse.
  • AES, graph/final proof encoding and v1 verification remain on their existing routes; typed SHAKE proofs are constrained through the request bridge.

N4 descriptor planning has 319 recursive proofs versus 523 with the machine route, excluding auxiliary branches (39.0% fewer). This is a proof-count reduction, not a measured full-workflow speedup. Both plans cover 536 native components.
