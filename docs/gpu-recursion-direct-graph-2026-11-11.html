Architectural changes

  • Default typed graph aggregation combines up to eight native graph leaves in one proof for N4 (up to four for N3), eliminating the preliminary per-leaf dry compilation pass.
  • Direct typed graph parents enforce the registered plan, adjacent ordered coverage, context, statement and node-manifest bindings, with actual child-proof verification.
  • Complete typed graph roots feed directly into the existing ordered final aggregator without a bridge proof. The existing final aggregate proof/header encoding is preserved.
  • Graph groups use the bounded weighted CPU preparation queue and single GPU consumer, releasing source ownership before GPU proving and reusing exact-template public preprocessing.
  • Default typed graph and crypto reductions use at most four recursive children after the eight-child graph parent exceeded the measured device memory budget. Native graph groups remain up to eight; native crypto groups remain up to sixteen for N4.
  • An archive-only graph architecture benchmark revalidates exact native contracts and input digests, records fresh recursive proofs, and checks teardown and external GPU memory observations.

Parent and memory qualification

The four-child parent screen passed in 72.93 seconds: eight native leaf proofs, two four-child parents and one two-child root. All 11 proofs verified, with ordering and altered-public rejection checks.

An eight-child parent required 14.23 GiB of fixed device allocations, exceeding the 10.5 GiB managed allowance. That failed attempt was retained in the evidence. The default was reduced to four children and passed the GPU screen. Native graph groups still contain up to eight leaves.

Measured process GPU peak: 9.76 GiB for the parent screen. All qualified jobs drained the GPU queue, closed the context and reaped their subprocesses.

Validation and limits

39 focused Rust tests passed (2 ignored); 73 Python tests passed; the CPU-only feature check passed. Typed final-consumer tests compile and evaluate the real adapter and reject changed bindings.

  • Measured workload: eight contiguous GBound graph leaves (offsets 4 through 11) from transaction 0 of deterministic N4. This is a graph subtree, not a complete transaction graph or aggregate.
  • Per-sample timing includes archive reimport and current-contract native-proof verification, group compilation, recursive proof generation, independent CPU verification, and public mutation rejection. Native proof generation, initial workflow metadata preparation, and process/GPU-context startup are excluded; guarded wall time is recorded separately.
  • Baseline and candidate use identical archived native proofs, inputs, source revision, GPU, 10.5 GiB managed GPU allowance, and 36 GiB worker envelope. Their bounded compiler policies differ: standard production MachineAir with CPU lookahead versus the typed-batch policy.
  • Warm time is the median of samples 2 and 3. The typed path reuses one exact-template public preprocessing entry; every recursive proof is freshly generated. A full workflow has multiple distinct templates, so warm subtree speedup must not be extrapolated to the full workflow.
  • The four-child GPU parent screen uses eight singleton native groups, two four-child parents and one two-child root. It covers two reduction levels, not every possible heterogeneous full-workflow child geometry.
  • N4 proof counts are descriptor-planning results excluding auxiliary branches. Full N3/N4 execution, heterogeneous graph grouping, and final aggregate GPU execution were not timed in this pass. The typed final-consumer adapter passed CPU compilation/evaluation and mutation tests.
