CPU RingCT proof execution

The isolated cpu-proof-execution branch adds CPU paired wrappers, a bounded dependency scheduler, worker-local proving contexts, and retained immutable program preparation. It measures N3 and N4 proof slices with a fixed total of 16 compute threads. Production defaults are unchanged.

Machine-readable measurements, source inventory, receipt hashes, and proof digests. Base commit: f31da6afef2a87634a693aa6ceb9388c93eca018. The report describes a bounded first pass; it does not qualify complete CPU aggregation.

Each native slice proves one real batch from each of six arithmetic families, the first PP and HashAlpha SHAKE segments, and the first AES segment for every transaction: 27 proofs for N3 and 36 for N4. Recursive memory limit

The genuine two-child SHAKE wrapper compiled at 244,432 active rows and 262,144 padded rows. Its retained LDE alone is 29.5 GiB; the CPU work estimate is 42.375 GiB, before the output reservation. The tested graph parent has the same 42.4 GiB work requirement. Both exceed the approved 32/36 GiB logical limits, so neither parent proof ran. The implementation does not substitute singleton wrappers or weaken proof parameters. Complete graph proofs and final aggregation remain unprofiled.

Memory admission accounts for hiding-PCS salts, commitment trees, opening workspace, native buffers, and separately retained compiler/program inputs. It is a conservative research model, not an allocation-derived bound. The external 47 GiB N3 and 51 GiB N4 cgroups remain the hard process limits, with swap disabled.

Implementation and ownership

The coordinator owns the existing non-thread-safe ledger and original reservation tokens. Each owner creates and uses a private CPU context inside its local Rayon pool. No context or ledger crosses threads and no unsafe Send/Sync implementation was added. Ready jobs are prioritized by estimated remaining dependency-path cost, with measured costs used on subsequent repetitions and prepared-program affinity on ties.

Memory is reserved before dispatch. Compiled output claims retain their original token and split off unused capacity after compilation. A retained program keeps its compiler-input originals and conservative CPU work envelope until its owner acknowledges eviction or exits. Idle preparation is evicted when it prevents progress; all workers are joined before originals are released, including failure paths.

cpu-proof-experiment rejects OpenCL and deterministic private-entropy features. The explicit CPU paired API checks fresh-proof cache policies and canonical paired coverage. CPU contexts use the standard 32 GiB or explicit 36 GiB research profile; the existing legacy CPU constructor and GPU route retain their original admission rules.

Validation and measurement scope

Passed: 24 targeted Rust checks, one separately enabled test proving cached-program reuse with changed inputs and fresh randomness, and 42 Python acceptance/guard checks. Every measured proof is independently verified and rejects public-value and opened-proof mutations. Final accepted trials contain 1415 proofs; their serialized proof digests are globally unique: true. Paired analysis checks identical input digests, executables, source inventories, and workload selections before comparing timings.

Slice wall time includes proof serialization, mutation checks, and worker startup and teardown. The final build also waits explicitly for compute-thread and owner-thread local destructors. Earlier finalist slice timers did not explicitly join compute-thread destructors; their outer guard measurements still waited for terminal and reaped processes. Arithmetic proving includes witness generation and its first verification; a second verification is reported separately. Input loading, native verification, lowering, and plan construction are outside slice wall and captured as preparation time. Public fixtures were generated once with fresh private entropy and reused for matched measurements; no secret keys were exported.

Measured hardware: AMD Ryzen 9 5900XT, physical CPUs 0–15, CPU quota 1600%, Rust 1.96.0. The final generic and x86-64-v3 release builds are cpu-proof-build-r11 and cpu-proof-build-v3-r4. Native finalist comparisons used cpu-proof-build-v3-r3. The final build extends the public paired API's CPU memory check to merged parents and explicitly joins both compute threads and context-owner threads before releasing original reservations. Proof algorithms, dispatch priorities, and native proof adapters are unchanged. The earlier five-pair measurements precede that teardown fix; the final-build confirmations below are single-sample regression screens, not a replacement five-pair qualification. Each guard record pins executable and source hashes and confirms terminal/reaped processes. Both source inventories are archived. Reproduction

Use a new guard label for every job. Build from this worktree; a recorded build is required after source changes. Choose either the generic target or an explicitly supported x86-64-v3 target. Hardware jobs must remain exclusive.

python3 research/pq-ringct/tools/opencl_private_spend_validate.py   --profile build --label cpu-proof-build-example --seconds 1200   --build-cpu-target x86-64-v3   --record-artifact "$PWD/.tools/target-cpu-v3/release/pq-ringct-cpu-proof"   --execute --exclusive-window --   /home/access/code/lattica/.tools/rust-1.96.0/bin/cargo build   --release --locked --offline --manifest-path research/pq-ringct/Cargo.toml   --target-dir "$PWD/.tools/target-cpu-v3" --no-default-features   --features cpu-proof-experiment --bin pq-ringct-cpu-proof -j2

python3 research/pq-ringct/tools/opencl_private_spend_validate.py   --profile cpu-proof --cpu-proof --host-profile standard   --label cpu-proof-example --seconds 1200 --build-label cpu-proof-build-example   --execute --exclusive-window --   "$PWD/.tools/target-cpu-v3/release/pq-ringct-cpu-proof"   --case n3 --workload 0 --input "$PWD/.tools/cpu-proof/n3-w0.json"   --mode native-mix --workers 2 --threads-per-proof 8 --retain 0   --request 0 --segments 1 --repetitions 1

To generate a new public fixture, use a separate guarded invocation with a new output path and append --generate 1; generation refuses to overwrite an existing file. For N4 use --host-profile expanded-36 --case n4 --workers 4 --threads-per-proof 4. To measure retained PP preparation use --mode paired --request 0 --segments 1 --workers 1 --threads-per-proof 16 --retain 1, and compare with --retain 0.
