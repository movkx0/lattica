Implementation

Two- and four-state packed Poseidon2 kernels preserve the existing round constants, sponge behavior, salts, transcript, and reference verifier. The CPU identity prefix can run alongside preprocessing inside the existing Rayon pool. It requires a worker in a pool with more than one thread, at least 262,144 padded rows, and preprocessing-plus-prefix memory admission; other cases use the sequential path. The prefix is bound to the same immutable program and validated commitment geometry, and its scoped task joins on errors and unwinding.

The tested candidate uses --cpu-variant combined --cpu-hash-kernel existing --identity-overlap 1; the comparison harness invokes it through the existing resource guard. Normal defaults remain reference/existing with identity overlap disabled. Target comparisons reuse only verified public child proofs. Both arms freshly compile, register, prove, serialize, and independently verify their parent. Owners retire between arms, and proof entropy is fresh. The two-child wrappers and graph parents retain their genuine N4 geometry.

The first larger comparison stopped before parent proving because a blanket 64 MiB retained-child reservation could not fit within the existing logical cap. Its 52.80 seconds remain charged to the testing ledger. The final implementation counts the actual owned child proof and verifier backing, including spare vector capacities. Only the two final observations escape the comparison job, so its output reservation is 64 KiB; temporary proof buffers remain inside the existing 512 MiB work allowance. No resource cap was raised.

Native proofs and throughput

The N3 smoke check completed 27 proofs at two proofs × eight threads in 166.60s; its largest per-proof cold-time upper bound was 38.04s.

N4 retains four proofs × four threads. Each batch contains four instances of each of six arithmetic families and three cryptographic families (36 representative proofs); these are component slices, not a complete transaction workflow. Three alternating pairs measured median batch times of 221.750s reference and 220.501s candidate (0.79% median paired reduction). Peak process memory: 36.714 → 32.738 GiB.
