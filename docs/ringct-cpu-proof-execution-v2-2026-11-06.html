RingCT CPU proof execution v2

6 November 2026 · isolated cpu-proof-execution-v2 branch · base 5ce4fca

This pass adds bounded commitment hashing, private salt replay, streamed opening reduction and phase-aware memory admission. The larger N4 two-child SHAKE and graph-parent slices now verify within the existing 36 GiB logical and 51 GiB process limits. The reference implementation remains the default.

Machine-readable evidence contains every receipt, source inventory, executable and input hash, accepted proof digest, and failed or stopped attempt. Historical results remain in the previous report.

Implementation

  • Explicit variants: reference, hash, memory and combined are carried by each worker context. There is no process-global selection; reference stays default and GPU dispatch is unchanged.
  • Commitment hashing: bounded packed leaf tiles use contiguous source-row reads. Hash and combined select 256 rows, with a total 64 MiB scratch allowance per proof. Mixed heights and Merkle caps preserve reference commitments and openings.
  • Private salts: one ChaCha state checkpoint per 1,024 rows replays the exact rejection-sampling stream. Fresh proof entropy is retained; checkpoints stay private in RAM and are never serialized.
  • Opening reduction: an opt-in patch to pinned p3-fri 0.6.1 streams row compression into reduction and releases interpolation weights, coset data and denominator vectors after their last use. Matrix/point/challenge order and proof encoding stay unchanged.
  • Ownership and admission: worker completion shrinks prepared claims to measured owned backing plus a 512 MiB auxiliary allowance. Subsequent hits reserve their remaining scratch. Ready proofs run before new roots; terminal outputs retire after verification, and a cache hit that cannot acquire scratch is evicted on its owner. Original reservations survive errors until owner and compute-thread joins.

Validation and provenance

1558 accepted proofs have distinct serialized digests. Every accepted proof passed reference verification and public-value/opening mutation checks. Focused Rust checks cover transcript equality, mixed heights, salt rejection replay and boundaries, cache reuse with changed inputs and fresh entropy, reservation shrink/eviction, terminal retirement, and cleanup after errors and panics. The final scheduler suite passed 12 tests; shared salt/commitment checks passed 4 on both generic and x86-64-v3 builds, research checks passed 26, explicit freshness checks passed 2, and Python acceptance/guard checks passed 45. The existing OpenCL feature also compiled; no GPU profiling ran.

Charged profiling time: 13066.0 / 14,400 seconds, including all failed, refused and stopped profiles. Component/pilot screening used 989.7 / 1,200 seconds; large attempts used 1981.9 / 2,400 seconds. Builds and unit compilation are excluded. Each hardware job is exclusive and capped at 1,200 seconds. Hardware: AMD Ryzen 9 5900XT, physical CPUs 0–15, quota 1600%, Rust 1.96.0. Final generic and x86-64-v3 builds are cpu-proof-v2-generic-build-r5 and cpu-proof-v2-v3-build-r5.

Early large attempts exposed retained compiler-output pressure. The first changes prioritized ready consumers and retired terminal proofs; the final fix evicts retained preparation when its old compiler original prevents scratch admission. Their failures remain recorded. The externally cancelled SHAKE-r3 guard was killed before it could finalize: its original “starting” receipt is preserved alongside a separate cancellation receipt, which confirms no live process and charges 310.350547 seconds conservatively. It contributes no accepted proof result.

Slice time includes serialization, verification, mutation checks, and owner/compute-thread teardown. Input loading, native input verification and lowering are recorded separately as preparation time. Outer guard time includes those costs. No complete aggregation or GPU qualification is claimed.

Reproduction

Use a fresh label for each exclusive guarded job. Build labels pin the executable and complete source inventory. Existing fixture paths are public input fixtures reused from the earlier campaign; copy them to the displayed path before reproducing in another checkout.

python3 research/pq-ringct/tools/opencl_private_spend_validate.py \
  --profile build --label cpu-proof-v2-example-build --seconds 1200 \
  --build-cpu-target x86-64-v3 \
  --record-artifact "$PWD/.tools/target-cpu-v3/release/pq-ringct-cpu-proof" \
  --execute --exclusive-window -- \
  /home/access/code/lattica/.tools/rust-1.96.0/bin/cargo build \
  --release --locked --offline --manifest-path research/pq-ringct/Cargo.toml \
  --target-dir "$PWD/.tools/target-cpu-v3" --no-default-features \
  --features cpu-proof-experiment --bin pq-ringct-cpu-proof -j2

python3 research/pq-ringct/tools/opencl_private_spend_validate.py \
  --profile cpu-proof --cpu-proof --host-profile standard \
  --label cpu-proof-v2-example --seconds 1200 \
  --build-label cpu-proof-v2-example-build --execute --exclusive-window -- \
  "$PWD/.tools/target-cpu-v3/release/pq-ringct-cpu-proof" \
  --case n3 --workload 0 --input "$PWD/.tools/cpu-proof-v2/n3-w0.json" \

Retained PP uses --mode paired --request 0 --segments 1 --retain 1 --workers 1 --threads-per-proof 16. The larger SHAKE run uses N4 input 0 and --mode paired --request 1 --segments 2; graph parents use --mode graph-parent --request 4 --segments 2, both at 1 × 16 with retention.
