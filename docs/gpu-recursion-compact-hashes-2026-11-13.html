Compact recursive hash traces

2026-11-13 · GPU recursive aggregation · default implementation

Hash lanes now store the permutation inputs once and authenticate the raw values through the wire lookup. Eight consecutive output addresses are represented by one checked base address. Each lane uses 95 rather than 103 witness columns and 28 rather than 35 preprocessing columns.

The change is retained after complete subtree measurements. The gains are modest: the fresh graph comparison improved by 3.7%, and SHAKE improved by 2.6% against its earlier matched baseline.

The graph comparison repeated the baseline using its original verified binary and exact sources. Parent GPU proof time averaged 12.13 → 11.36 seconds (6.3% lower). Parent logical committed LDE fields fell by 3.1% for graph and 2.6% for SHAKE. This is total proof work, not resident memory.

The twelve-leaf group completed three verified proofs in 42.97 seconds. Its older reference has other compiler differences, so this pass claims no speedup for that larger group. No fresh full N4 workflow was run.

All 33 candidate workload proofs passed independent CPU verification. Existing cryptographic parameters and CPU verification requirements remain unchanged. The new lookup expressions increase permutation columns from 18 to 27 per hash-table row; measured gains already include that cost. Template identities change so prior public-template cache entries cannot be reused.

New tests exercise duplicate inputs, earlier arithmetic uses, both swap directions, a direction-bit mutation that passes local constraints but fails the global lookup, and malformed output addresses. An initial test incorrectly expected three net provider uses; correcting it to two changed no production code. The complete corrected suite passed. These checks are correctness evidence, not a formal security audit.
