Measurements, source hashes and validation receipts · Previous report

  • The default typed GPU aggregation batch-query path automatically uses sparse child-pair transfers when they are smaller than a full-tree reload. Existing scalar, device-retained, and small-tree routes remain supported. No new opt-in flag was introduced.
  • Host code copies contiguous pairs of existing child digests into the already allocated pinned staging buffer. The GPU uses the original query index to select each sibling and assemble the path. The host does not recompute hashes, change challenges, or synthesize final authentication paths.
  • The three-proof pipeline includes CPU compilation, template preparation, witness generation, GPU proving and CPU verification. It excludes OpenCL context/program initialization. The comparison is against the prior accepted r104 run on identical archived inputs, proof geometry, cache behavior, workers and budgets; it is not a randomized ABBA comparison or a confidence interval.
  • Reload statistics cover host-to-device transfers of completed retained trees for queries. Construction and initial device-to-host tree offload remain unchanged. The largest-query-source comparison is one temporary allocation, not the peak total GPU memory for the proof.
  • Correctness tests cover CPU/scalar path equivalence, repeated and unsorted queries, leaf/cap boundaries, 15-level paths, 1/2/128/256 queries, multiple staging chunks, invalid indices, stale epochs, injected failure cleanup and a GPU budget that cannot hold a full-tree reload. Existing CPU verification and statement-mutation rejection remain enabled in the proof checks.
  • Transaction generation, complete fresh N3/N4 aggregation, heterogeneous sixteen-leaf groups and macOS were not measured. The primary screen covers twelve GBound leaves; the hierarchy covers eight singletons and a parent; the crypto screen covers one complete SHAKE request.
  • No proof constraints, cryptographic arithmetic, transcript, randomness, query count or blowup changed. This transfer optimization does not resolve the previously documented complete-tree soundness and zero-knowledge review gaps.
