November 8, 2026. Deterministic N4 subtree qualification on an RTX 5080, driver 615.78.08. This extends the v3 consuming pipeline at commit 17e4c8a. Full N3/N4 aggregation remains unqualified.

Result

The opt-in grouped-v4 profile supports an immutable 8–12 GiB managed budget, guarded available-memory selection, qualified smaller context reserves, one-kernel batched Merkle query gathering, and full backend admission before wider groups are proved. Existing profiles retain their 8 GiB managed / 4 GiB context defaults. The measured settings did not meet the 10% promotion threshold.

Budget growth from 8 to 10.5 GiB increased transform tile widths (large plans move from 1–4 to 4–16 columns) and peak managed use from about 7.81 to 10.26 GiB. For the large transforms, the next 32-column tile would need a 4 GiB allocation, exceeding the device’s approximately 3.89 GiB per-allocation limit. The existing default remains appropriate.

Memory qualification and wider groups

The guard resolves auto once as the minimum of 12 GiB, OpenCL global memory minus reserve and 512 MiB, and NVML free memory minus the same allowances, rounded down to 256 MiB. On this host the original 4 GiB reserve admits 10.5 GiB. Synchronized registration, trace, LDE, query and proof-completion checkpoints qualified a 2 GiB reserve, then verified the 12 GiB managed envelope. Independent process-memory sampling remained active. No allowance grows during a proof.

The reusable 12 GiB qualification observed at most 271.79 MiB beyond live tracked allocations. It is bound to the source, executable, GPU UUID, driver, batch-gather mode and these exact (rows, public values) shapes: [{'rows': 262144, 'public_values': 46}, {'rows': 524288, 'public_values': 28}, {'rows': 524288, 'public_values': 46}]. Other shapes require qualification or the original reserve. The 2 GiB minimum includes at least 512 MiB above the observed peak.

Width-eight graph compilation was refused at the 2 GiB compiler scratch limit before any proof was dispatched, then split into width-four groups. SHAKE's source/row planning also kept its largest admitted group at four. Extra GPU memory does not remove those source-construction limits. The selected N4 metadata plan is a planning result, not proof that the whole graph fits or completes.

Exploratory r22 runs exposed an interaction: lowering the reserve disabled an older specialized-quotient gate and increased graph time to 61.67 seconds. The corrected r23 build permits that kernel only with validated v4 qualification; the final comparisons above use the same corrected source. The earlier source also supplied memory-only/batching-only screens and the width-eight refusal evidence; their summary records and original fingerprints are preserved in the machine-readable evidence.

Correctness and isolation

Eight core CPU tests, 27 research tests, 55 Python controller tests and two guarded GPU correctness tests passed. Batched paths match CPU and scalar results for 1, 2, 128 and 256 queries, including duplicates; tests cover invalid bounds, epoch mismatch, cap-only trees and injected-error cleanup. Fresh consuming proofs verified independently and rejected altered public inputs. All 128 recursive proofs in the measured screens/diagnostics verified. Sessions drained queues and closed. Legacy GPU and CPU feature checks passed; these Linux checks do not qualify macOS.

All hardware jobs used the exclusive zero-swap guard. Builds were excluded from the persistent test ledger; tests, preparation, screens, qualification and selection were charged without resetting historical attempts. Remaining test budget: 76.5 seconds of the authorized 9,000-second cumulative ledger.

Use and evidence

The new options are restricted to --profile grouped-v4 --pipeline lookahead --identity cpu: --gpu-managed-mib auto|N, --query-gather batch|scalar, and --memory-qualification FILE. First use qualify-memory at an already admissible envelope with --output FILE. The guard publishes a qualification only after proof verification, source/executable checks and process reaping. Combine compatible family records with gpu_aggregation_memory.merge_qualifications. Selection files bind effective memory and gather settings. Source or binary changes invalidate saved qualification.
