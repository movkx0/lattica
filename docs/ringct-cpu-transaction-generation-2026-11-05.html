CPU transaction generation for the RingCT research workflow

The fresh N3/N4 entry now generates transactions on the native CPU backend, independently verifies each public output, clears private state, and consumes the CPU owner before opening the GPU planning context. GPU arithmetic and recursive proof requirements are preserved. The prior full-workflow campaign and automatic promotion remain canceled.

The branch is transaction-generation-cpu, based on c71ecc7. Machine-readable results and receipt hashes accompany this report. This qualification covers CPU generation, complete metadata handoffs, and focused GPU proofs. Full recursive aggregation was not resumed.

Optimization decisions

The reference C backend already uses AES-NI, AVX2 and FMA. The implementation adds a bounded reusable workspace, fresh private entropy, retry/RNG/proposal limits, per-stage counters and a single-entry public-parameter cache option. Every C call remains serialized by the native lock; no generation GPU context is created.

Three paired screens used identical deterministic diagnostic transactions and alternated variant order. After replacing byte erasure with volatile vector stores and specializing the lane loops, four-block AES improved single-transaction medians by 1.65–2.05%, and eight-block AES by 2.04–2.37%. Public-cache batch improvements were at most 0.30%. Neither met the agreed 5% median gate. The default remains scalar AES with no public cache; the measured variants remain explicit benchmark options. Diagnostic entropy is isolated behind native-generation-oracle and is refused by the workflow and fresh-entropy benchmark.

Ownership and validation

Generation preissues input, operation, verifier and shared-state claims in the original ledger. CPU dispatch checks those originals. A typed verified output prevents duplicate native verification, and a typed CPU terminal is minted only after workspace destruction. CPU terminals carry no GPU session identifier. GPU planning starts through the existing constructor after that terminal; it retains the same ledger.

The native source census was extended and source pins refreshed. All 317 native numeric catalog rows remained unchanged. The existing 72 registered rows were unaffected. Fresh N3/N4 metadata runs recorded 0 cold compiler misses out of 2,366 and 3,154 requests respectively; metadata took 2.006 s and 2.581 s with 2 and 4 workers. Their 6 and 8 observed GPU metadata receipts followed CPU retirement.

Validation passed: AES streams/counters/tails against an independent AES implementation; deterministic transaction parity; entropy and limit refusals with cleanup/recovery; fresh-entropy verification and mutation rejection; 11 source/ownership checks; 8 native adapter regression checks; 228 focused Python checks; and 24 focused GPU proofs with 24 independent CPU verifications and 24 rejected mutations. Release builds of the generation benchmark and workflow CLI passed. Full-workflow speedup remains unqualified.

Reproduce a generation measurement

Run from this worktree and choose unused guard labels. A new recorded build is required after source or guard changes. The guard executes one hardware job at a time.

python3 research/pq-ringct/tools/opencl_private_spend_validate.py --profile build --label txgen-build-example --seconds 1800 --record-artifact "$PWD/.tools/target-opencl/release/matrict-bench" --execute --exclusive-window -- /home/access/code/lattica/.tools/rust-1.96.0/bin/cargo build --release --locked --offline --manifest-path research/pq-ringct/Cargo.toml --features native-matrict --bin matrict-bench -j2

python3 research/pq-ringct/tools/opencl_private_spend_validate.py --profile research-compile --label txgen-n1-example --seconds 1800 --generation-only --build-label txgen-build-example --execute --exclusive-window -- "$PWD/.tools/target-opencl/release/matrict-bench" generation --transactions 1 --samples 100

Use --transactions 3 or 4 with --samples 10 for batches. Experiments select --aes-lanes 4|8 or --cache-public-parameters 1. Public seeds and contexts accept exactly 64 hexadecimal digits. Retained JSON receipts bind the command, source inputs, executable, log and terminal cleanup.
