V100 prover: internal matrix reduction and shared quotient inversion

20 October 2026 · Fifth optimization pass · Tesla V100-PCIE-32GB

This run compares the previous external_brev release with internal_inverse. Both use fresh proofs, the same fixtures and the same independent CPU verifier binaries. Earlier campaign evidence remains intact.

All seven aggregation pairs improved: median latency fell 1.14% for four inputs, 2.47% for eight inputs and 1.56% for two concurrent eight-input jobs. Native results were mixed: its pooled median was 1.12% slower, with six wins in twelve pairs and a median paired reduction of -0.13%. This run establishes no native speedup. The candidate is retained for its consistent aggregation gains on the tested V100 fixtures.

Changes and arithmetic bounds

The fast Poseidon2 internal layer now combines the diagonal with unreduced low/high 32-bit state sums and reduces once per output. Negative coefficients add an integer multiple of the field modulus before subtraction. All limb accumulators stay nonnegative and below 12 × 2³², inside the shared matrix reducer's 21 × (2³² − 1) bound. The existing diagonal-parameter guard and generic fallback remain in place.

Goldilocks inversion now uses a fixed public addition chain: 63 squares and nine other multiplications. Its exponent is exactly p − 2, including the previous zero-to-zero behavior for zero field representatives. All constant p − 2 exponentiations in the OpenCL engine use this helper.

The quotient kernel shares one inversion of z × (x − 1) × (x − trace_last) across its three denominators. Seven multiplications recover inverse_z and the first/last selectors. The existing nonzero-domain guard runs first, and its rejection sentinel is unchanged. No cross-thread synchronization or additional buffers are needed.

Validation

42 targeted tests passed, plus CPU-only and GPU-without-tuning compilation. New integer oracles cover the inverse chain over arbitrary u64 inputs and both extension degrees of the actual quotient kernel, including invalid domains, noncanonical inputs, output offsets and padded launches. The permanent internal-matrix oracle now covers 66,836 states for each guarded/default/custom diagonal path. Isolated screens also check complete permutations.

The benchmark ledger contains 60 independently CPU-audited outputs representing 192 fresh benchmark proofs. Output hashes are unique, every required GPU stage is covered, and native public-input tampering is rejected. All 690 selected source-file hashes match release and test builds.

Other candidates screened

  • sum_bounded: 1.08-2.41% rowhash gain is smaller than folding the entire internal matrix
  • internal_common: Correct, but lower gain than per-coefficient offsets on four of six shapes in the follow-up screen
  • inverse_chain_only: Reduces inversion cost but retains three quotient inversions
  • batch_binary: Correct and faster, but slower than combining shared-product inversion with the fixed chain

Timer boundaries

  • Four-input aggregation: Aggregation call plus GPU drain; excludes context initialization, artifact output and CPU audit.
  • Eight-input aggregation: Cohort launch to worker exit; includes initialization, start barrier, aggregation, artifact output and shutdown; excludes CPU audit.
  • Two concurrent eight-input jobs: Cohort launch to last of two worker exits; includes both initializations, start barrier, aggregations, artifact output and shutdown; excludes CPU audits.
  • Native JoinSplit: Native ABI proving call plus GPU drain; excludes context initialization, buffer setup, artifact output and CPU audit.

Research used

  • NVIDIA Volta Tuning Guide: Guided measurement of arithmetic dependency chains and register-resource tradeoffs; decisions use actual V100 timings.
  • Plonky2 Goldilocks inverse implementation: Documents the 72-multiplication addition chain for p-2. The OpenCL implementation was independently checked with integer exponentiation.

Scope and limits

  • One Tesla V100-PCIE-32GB, fixed aggregation fixtures and bounded resource settings.
  • Three four-input pairs, two eight-input pairs, two concurrent pairs and twelve native pairs; limited sample counts.
  • Warmed alternating pairs. First-use profiles and warmups are retained but excluded from the qualification medians.
  • Both pooled medians and within-pair reductions are reported; short native calls remain sensitive to timing variation.
  • Kernel event totals and inclusive host spans are not additive; gaps in event coverage do not establish GPU idle time.
  • No cold-cache, Apple GPU, full-block or production qualification in this run.
