GPU recursion: verified parents and a complete SHAKE subtree

The new backend now verifies child proofs inside constrained parent programs and merges multiple children while enforcing interval coverage, order, statement context and endpoint continuity. All 24 GPU proofs in the accepted profiles passed independent CPU verification.

The complete ten-component SHAKE request uses three wrappers and one root. Three samples took 36.74, 36.66, and 36.58 seconds. The warm median is 36.62 s. Native import verification, compilation and preflight took 3.32 s separately; the first request including that work took 40.06 s, excluding process startup.

The saved v1 result used five proofs and had a 68.55 s warm median on the same deterministic input hash. The ratio is 1.87× for the prepared candidate; charging its native preparation to each request gives 1.72×. Different source and compiler policies prevent treating this as a matched full-workflow qualification.

Peak managed GPU allocation was 10.03 GiB inside the 10.5 GiB allowance. The standard compiler limit rejected the three-child root; the existing two-million-input research policy passed inside the 36 GiB host guard.

Validation and remaining gates

Eight core parent/legacy checks, 20 research checks and 67 Python checks passed. The CPU-only configuration compiles. Negative tests cover altered openings and balanced lookup terminals, wrong trusted keys, changed public values, missing/reordered intervals, and valid child proofs with inconsistent endpoints or statement context.

Production defaults remain unchanged. This qualifies a complete SHAKE request subtree, not an N3/N4 transaction aggregate. The 2× promotion target, larger fan-in and native groups, graph/transaction integration, scheduling and the V2 aggregate artifact remain open. Repeated public setup is the next measured target: it costs about 8.28 s per request and needs bounded retention or eviction within the GPU allowance.
