Measurements, source hashes, receipts and validation details · Previous optimization report

  • Compilation comparison uses two fresh complete programs and two fresh prover programs in ABBA order on one OpenCL context. Each program exports a distinct trivial kernel to force a new program binary without changing or deleting shared driver caches. It measures program compilation, not a fully cold machine or driver, and is not a statistical confidence interval.
  • The default typed aggregation program omits twelve native transaction/source-generation modules. Native preparation, machine reference paths, and fixed owned runtimes retain the complete program. There is no fallback to CPU proving or implicit switch to native kernels inside a prover-only context.
  • The compilation test is a test binary and includes the existing random-reference test fragment; the runner omits that test-only fragment. Timings are separately reported for actual runner context/program creation.
  • Historical first-compilation three-proof job wall time was 90.23 seconds in r103 and 65.60 seconds in r104. These are separate revision runs including controller and initialization overhead, not a controlled fresh-program comparison. The ABBA compilation test supplies the direct startup comparison.
  • The three-proof pipeline timer excludes context and program initialization. Its before/after comparison uses the prior accepted r103 result and current r104 result on identical archives, proof counts, geometry, worker settings, cache behavior and memory limits. It establishes no major steady-state proof speedup.
  • Transaction generation, complete fresh N3/N4 aggregation, heterogeneous sixteen-leaf groups, and macOS are not measured by this pass. The graph screen covers twelve GBound leaves; the separate hierarchy covers eight singletons and their parent; the crypto screen covers one complete SHAKE request.
  • Proof arithmetic, constraints, transcript, randomness and security parameters were not changed. This startup optimization does not resolve the previously documented complete-tree soundness and zero-knowledge qualification gaps.
  • The allocation-free source registry now supplies the exact emitted byte order to both startup censuses. This also fixes drift in the old RingCT census and the omitted empty Poseidon-define separator in the note census. Existing opaque driver, host and device budgets remain unchanged.
