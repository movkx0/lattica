# Exhaustive request-parent source and registration-cap provenance

The source planner below composes the existing bounded registered-machine verifier planner
with the exact component merge adapter. It creates no native or recursive
proof, parent compiler program, verifier, GPU runtime or dispatch capability.
The separate test-only B053 acceptance and B054 first-two-parent compiler
prerequisites are documented in `capture/acceptance/BOUNDS.md` and
`capture/acceptance/parent/BOUNDS.md`; they do not make this source planner
an execution or whole-request admission entry.
B051's uninhabited complete-request success type and production PairedV1 refusal
remain unchanged. A036's admitted original native phase geometry is separate
evidence; these additional owners must reduce the original native PCS capacity
before any future complete-request attempt.

`ParentSourcePlan` accepts only an original B051 request owner retaining all
five genuine B050 leaf-source owners. The original request pointer, ledger,
fixed metadata requirement and existing 32 GiB host / 8 GiB managed-device
ceilings are checked. Leaf source padded-height bounds must fit the unchanged
2^20 row ceiling. No caller-selected shape, footprint, cap, report, program or
proof can construct a returned parent-source bound.

The planner reserves the complete `PlanningStorage::for_children` requirement
for a width-46 machine child at the unchanged 2^20 ceiling, plus its complete
caller and retained metadata census. It invokes the existing
`verifier_height_envelope` once: all eighteen power-of-two heights from 8
through 2^20 are inspected using private invalid proof templates and unknown
public/proof/cap wires. Every template/program/symbolic payload is destroyed
before the original temporary claim is released. Only numeric source counts
and metadata remain, retaining a borrow of the original five source owners.

No monotonicity of emitted operation counts in log(height) is assumed. The
core envelope takes independent scalar/cubic/Poseidon/wire/input maxima over
the complete finite domain. The pinned source-storage formula is checked by
the existing envelope at every height. Its reported program-requested peak is
a planner observation, never a specialized compiler memory allowance. The
future real compiler still requires its own enforced full 2 GiB construction
ceiling and all caller/input/symbolic/proof/output lifetime claims.

Two independent core bounds are summed and the component adapter is added
before row packing. The adapter contributes 1,419 scalar operations: 1,332
for eight bounded-32 context words and fixed profile/contract/span/descriptor
fields; 87 for shared-header, first/adjacency/count and endpoint equalities.
It adds no cubic or Poseidon operation. The maintained `bind_merge` predicate
is called through a private fixed-array emitter; preexisting or resulting
builder resource failure is rejected. The emitter supplies no allocation or
proof acceptance authority. The source test creates a bounded framing-only
program and mutates every shared header, span and interior/end-root field.
Child LEVEL is intentionally owned by its authenticated registered predicate;
the framing-only program is not a replacement for that child verifier.

The composition uses the same restricted fresh-input/opaque-cap specialization
argument pinned in `shape/OPAQUE_CAPS.md` and
`shape/REGISTERED_DESCENDANTS.md`. Constant/hash sharing cannot introduce work
under those closed paths; no general optimizer monotonicity is assumed.
Wire bounds add both core maxima, outer public wires and at most one wire per
adapter scalar instruction. Inputs add the two core maxima. Any operation,
wire, input, row or integer overflow refuses the source pass. Since all leaves
and the derived parent bound fit the same exhaustive domain, the fixed four
parents close inductively, including the final level-2/level-0 asymmetric merge.
This establishes only request-parent source geometry if qualification passes.

The separate `PreissuedLeafCap` retains an original fixed cap/caller claim
inside `RegisteredMetadata`; it is issued from that original parent-source
owner before any planned native attempt. Capturing requires the exact genuine
`OwnedCompiledShake` to pass its original leaf `GroupSourceBound::check_compiled`.
It then requires pointer equality between the compiled `Program` allocation
and `RegisteredProgram::air().program()`. Equal manifests, summaries, heights
or witness values are insufficient. The actual registration must expose the
canonical 64 roots with exactly that backing capacity. The capture copies
only those actual roots into a fixed array while the original claim is live.
No caller-provided cap or transport key is accepted. The captured owner keeps
the compiled/source borrows and original reservation; it offers no raw cap
getter or constructor, accepted-child conversion, proof method or dispatch.

This cap seam establishes actual registered-program provenance only. It does
not authenticate an existing `RetainedNodeOutput`, its separate verifier cap,
a produced proof, transaction context, or runtime retirement. Its use in a
producer still needs the typed private attempt and one-shot completion contract
from `request_workspace/LIFECYCLE.md`, including independent verification under
that trusted cap. Repeated registrations of one original program are not a
substitute for that future attempt correlation. Existing output reports retain
their `authenticated_source_key=false` semantics.

Focused tests cover missing original leaf owners, foreign ledgers, finite-height
domain and overflow/row/wire/input rejection, actual framing mutation rejection,
and rejection of a separately allocated program with identical public shape.
The latter test creates no registration or proof and cannot manufacture a cap
owner. A separately guarded ignored source qualifier inspects all five genuine
leaves and all eighteen registered heights, retains five original cap claims,
confirms terminal category cleanup and preserves B051's complete-request
refusal. It produces zero native/recursive proofs and does not exercise the
capture with a genuine registration. That remaining qualification must use a
fully admitted producer; no standalone unbounded registration is introduced.

Still missing are independent parent CPU-verifier/caller lifetimes, the complete
authenticated parent compiler/output graph, correlated
compiler/runtime transfer, complete retained parent outputs/keys/reports,
artifact round trips and consuming transaction/final aggregation closure.
Builds, tests and GPU work are coordinator-only. Rustfmt parsing, source review
and pinned-capsule checks are not execution, memory-peak or performance evidence.
