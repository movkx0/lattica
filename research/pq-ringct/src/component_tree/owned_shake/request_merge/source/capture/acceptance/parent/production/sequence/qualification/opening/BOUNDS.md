# Exact original-root opening qualification driver

This inactive private driver selects the existing B066 opening action through
one original HashX Attempt. It adds no ancestor declaration, wrapper, CLI,
production acceptance, or dispatch authority. Existing transport and public-only
qualification drivers are unchanged. Request/group construction, numeric
projection, graph reporting and runtime guards reuse the parent helpers.

The complete baseline-plus-additive caller requirement is admitted first, before
the environment guard, fixture arrays, request ownership, source planning or
reporting. A's separate `opening::claims` module measures this exact caller's
opening owner, plan, retained report, measurement, Result/Option/borrow, checked
arithmetic, formatting, returned-error and destruction frames. The caller does
not replace native, compiler, retained key/proof/runtime or CPU verifier claims.

`PreissuedRootOpening::reserve_before_native` is invoked on this actual parent
source before `Attempt::reserve_before_native`, hence before PendingNative. Its
two B066 original claims stay additive throughout the same source/request/ledger
Attempt. Before Attempt, the driver checks 18 CPU heights, one planned opening
probe, and `probe_host_bytes = probe_verifier_host_bytes +
probe_caller_host_bytes`. The claims event separately reports the complete
baseline-plus-additive `driver_host_bytes` and checked probe-plus-driver total.
That total is a subset of the complete source/Attempt snapshot, not a physical
memory measurement or complete component footprint.

The GPU branch consumes exactly that Attempt, reports its ten native proofs,
five recursive leaves and four recursive parents, then consumes that same
Component through `recheck_root_opening`. No detached proof, key, root or runtime
continuation is accepted. B066 checks its own Parent3 originals and exact source
identity before its closed adapter provides the actual retained proof.

B066 positively verifies the untouched proof, changes exactly the first local
permutation opening by Challenge::ONE, restores the exact saved word before
classifying the returned outcome, requires typed RelationRejected, and positively
verifies the restored proof. The driver only borrows the retained measurement
under its original owner and caller. It requires exactly two positive checks,
one typed opening rejection, restoration, positive timing intervals, and checked
positive-plus-mutation time no greater than the complete opening action time.
It reports `retained_output_restored=true`; it makes no claim that the proof was
continuously immutable during this separate experiment.

The complete retained report is dropped before attempt/opening options, parent
source, refused request closure, group plans and both original requests. The
caller ends last. Returned production errors are classified using fixed static
strings while Failure and the caller remain live. The closed request result
remains `Result<Infallible, RefusedRequest>` and must retain five original leaf
sources; no whole-transaction admission is created. There is no retry, fallback,
or second Attempt. Combining this action with transport in one run would require
a separately reviewed owner/action design; both existing methods consume self.

The terminal ledger check and fixed observer remain explicit, separately
process-audited harness scope. They receive no released worker/source-storage
credit and create no new quota ledger. `terminal_observer_bytes` is a positive
source-layout census no larger than 1 MiB; it is not admission or measured
physical memory. Successful completion is emitted only after exercise returns
and every original ledger category is zero. Both final events report process-only
observer scope, no released-claim coverage, and unfinished independent
process/engine/device audit. Their worst-case unsigned decimal and fixed-string
formatting is 986 and 626 ASCII bytes including newlines, 1,612 combined under
the 4,096-byte ceiling. No proof, key, packet, dynamic error or retained report
crosses this terminal boundary.

The separate ignored CPU capacity entry uses the source-only guard and existing
numeric `project` helper after admitting the same originals. Its foreign ledger
exists only for wrong-identity refusal, receives no quota, and supplies no
terminal-observer credit. It emits no actual proof, numerical check, mutation,
backend or GPU work and keeps component success false. CPU routing must retain
the existing research-compile-large profile; the GPU branch retains the full
GPU-required guard and FreshOnly generation. Worker/process/device, native,
thread, row and cryptographic limits remain unchanged.

This milestone is one first-local-permutation-opening probe. Other proof fields,
commitments, FRI paths, interior child boundaries, parent continuity, artifact
round trips, transaction context, full N3/N4 workflows, physical resource fit,
asynchronous cleanup and performance remain separate obligations. All broader
mutation/artifact/workflow flags stay false. Local restoration on returned error
or Rust unwinding does not qualify full runtime/process cleanup. Source review,
census tests and synthetic log fixtures are not actual proof/GPU evidence.
