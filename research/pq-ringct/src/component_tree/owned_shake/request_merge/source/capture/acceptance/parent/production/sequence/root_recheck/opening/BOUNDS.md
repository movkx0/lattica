# One original-root opening probe, inactive prerequisite

This source extension adds a separate private entry for one negative opening
probe on the actual final HashX root. No driver, ignored GPU selector, CLI,
manifest, production acceptance or dispatcher selects it. The B065 public-only
entry, immutable adapter, claims and reports remain unchanged. The new entry
must receive its own separately constructed owner; no B065 action gains an
opening-probe method.

## Original ownership and numerical checks

`PreissuedRootOpening::reserve_before_native` first reserves an additive fixed
caller allowance, then obtains B065's complete source/header/all-height CPU
claim. The future driver must call this before constructing `Attempt`, hence
before `PendingNativeHashx` or any native capacity assignment. Source+Ledger
alone do not enforce that temporal order, and the constructor name is not a
runtime phase guard. There is currently no caller that activates this entry.
Before activation, the coordinator must review an actual pre-Attempt callsite
and its separate fixed environment, driver census and terminal evidence. This
inactive prerequisite is not permission for late issuance or an in-flight
upgrade.

The consuming `Component::recheck_root_opening` checks its own actual Parent3
retirement originals, request identity, root acceptance and completed graph
counts. It moves only that same Component's root into a local AcceptedChild,
checks original source/ledger acceptance, and creates the private action. Its
own retirement/support/caller fields stay live through proof checking and
destruction. Neither the action nor the Component accepts a detached root,
key, proof, compiler or runtime continuation.

The action copies the already authenticated fixed cap and height. It records
the actual local output address as an opaque pointer used solely for equality.
It never dereferences, serializes or returns that pointer. A move or another
output refuses the address check. The sealed AcceptedChild/output adapters
provide the same retained output's original key, mutable proof and request.
No mutable proof reference, callback or clone escapes those adapters. Original
request, ledger, exact source spec, height, cap capacity/content, public shape
and immutable expected source header are checked before numerical verification.

The actual retained verifier must first accept the untouched proof. A private
guard validates exactly one opened-values instance and a present first local
permutation opening. It saves that cubic Challenge and adds Challenge::ONE.
While it is live, it exposes only a shared borrow of the proof to the verifier;
the Vec shape therefore cannot change. Drop restores the exact saved word.
On an ordinary return, restoration and an equality check precede typed outcome
classification. Only RelationRejected earns the one negative-probe count.
Admission, configuration, allocation, accepted mutation and panic never earn
credit. After that rejection, the untouched proof must verify a second time.

The guard also restores during Rust unwinding. There is no catch or retry in
the actual proof path. This local restoration property does not qualify
asynchronous GPU cleanup, whole-owner unwinding, process/engine/device teardown
or abort behavior. Those remain separate experimental obligations.

## Additive memory and report lifetime

No proof/key clone, artifact, decoder, serialization buffer, dynamic mutation
list or new backend is created. The original retained proof/key and actual
runtime retain their existing claims. B065's base claim independently retains
the complete CPU lifecycle across all18 heights, typed classified-call extra,
fixed header/public/source helper storage and its original forwarding frames.

The additional PhaseScratch requirement includes eight complete layouts of the
new preissued owner/results, retained report/results, plan and measurement
reports, action including full fixed cap, guard/results, saved Challenge,
mutable/shared borrows, opaque pointers, ownership/result/error forwarding,
timer/checked arithmetic helpers and bounded diagnostic/drop overlap. No reuse,
inlining or mutually exclusive branch credit is taken. It is admitted inside
the unchanged32GiB worker host allowance and has no device charge. The existing
8GiB managed/4GiB context/24GiB native/47GiB process/zero-swap limits are unchanged.

The returned diagnostic owner retains both original reservations; its report
is non-Clone/non-Copy and can only be borrowed while the owner remains live.
The actual proof is destroyed before this diagnostic owner leaves the consumed
Component method. Its original reservation dies after its report. Caller-side
formatting/terminal reporting still needs a separately admitted future driver;
this source introduces none. Returned errors destroy the guard, output and
Component owners under the still-live preissued and existing caller claims.

## Scope and remaining interior checks

The result means exactly two untouched positive checks and one first local
permutation-opening rejection on the original final root. It is not complete
raw-proof coverage: commitment caps, FRI paths, other openings and proof fields
remain unprobed. It performs no interior-boundary mutations, artifact round
trip, transaction-context authentication, complete RingCT workflow or speed
measurement. Future reports must keep all those global qualification flags
false and label this result as a single root-opening probe. They must describe
the output as restored, not continuously immutable during this separate action.

Interior outputs are consumed while parents compile; a final-root probe cannot
retroactively test their boundary fields. A later extension should preissue one
sequence-owned all-height verifier/copy allowance before Attempt, then perform
fixed public probes on each exact accepted child before State::take_children
consumes it. The five leaves and four parents need separate ordinal/source/cap
binding and positive/probe/positive records. Parent-child ordering and every
boundary field also need relation-specific checks at their actual compiler
input boundary. Public rejection by an individual child verifier alone cannot
establish that the parent enforces continuity. No external child constructor or
generic mutable output callback should be introduced to manufacture those tests.

Four authored tests cover absent slots, exact restoration before every typed
outcome, synthetic unwind restoration, and additive exact/one-byte-short
admission. The fixture is a fixed Challenge owner, not a numerical proof or GPU
runtime. No test, build, parser, planner, auditor or GPU qualification was run by
B. Actual ignored selectors, corresponding guards, physical admission and
terminal audit remain unimplemented and unqualified until separately reviewed.
