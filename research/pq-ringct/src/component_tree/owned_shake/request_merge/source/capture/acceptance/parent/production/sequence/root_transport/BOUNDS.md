# B067 private same-Component root transport composition

This inactive source prerequisite consumes one completed original HashX
Component and checks its actual final SHAKE root in memory. It adds no module
wiring, driver, selector, CLI, manifest, proof dispatch or production acceptance.
The coordinator owns the separately reviewed immutable output adapter and
ancestor wiring. A owns admission.rs and admission/*; C owns header.rs and
header/*. All exact payloads and their combined memory census require review.

## Same original owner and sealed adapter

`Component::roundtrip_root` accepts only that consuming Component, A's opaque
preissued transport owner and the original Ledger. It checks its actual Parent3
retirement, original request, graph counts, root acceptance and source flags.
It then moves only its own root into a local AcceptedChild and checks the exact
source/ordinal/original ledger. The remaining Component originals, support and
caller stay held throughout the action and actual root destruction.

The private RootTransportAction constructor binds shared references to that
AcceptedChild, the same transport owner and Ledger. The immutable retained-output
adapter forwards only its own owner/key/proof/request fields after its existing
source and verification flags pass. There is no raw getter, arbitrary callback,
mutable proof borrow, detached root tuple or continuation conversion.

Before any codec operation, the action verifies pointer equality of the actual
owner, source and request; original-ledger membership; the source-derived root
Spec and first 38 public values; the actual accepted height; exact cap content
and capacity; and all 46 public values' fixed shape. Pointer identities are never
dereferenced as raw pointers or serialized. C's borrowed header view then holds
only actual local public/cap values and height, without authentication authority.

This proves only local component-source binding when the operation succeeds.
It does not authenticate a MatRiCT transaction, an obligation manifest or the
complete transaction context. Both transaction_context_authenticated and
workflow_admitted remain false; no output acceptance token is returned.

## Preissue and complete live storage

A's opaque transport owner must be constructed by a future reviewed driver
before Attempt, PendingNative and all proof dispatch. Source+Ledger and the
constructor name do not enforce that temporal ordering. No such driver or
temporal token is provided here, and the operation must remain inactive until
its separate callsite, whole-driver census and terminal audit are reviewed.

The action admits no new storage and has no retry or fallback. A retains its
original fixed caller/header/codec/report/error/destruction claim and additive
payload claim through the final borrowed report. The payload claim covers the
full 64 MiB cumulative decoder/canonical backing, two full 2 MiB packets and the
all-18-height independent CPU verifier lifecycle/classified-call increment.
Existing root/proof/key/runtime/support owners remain separately charged.

Both complete packets include C's 2,480-byte outer header inside the unchanged
2 MiB cap. Before Attempt, A checks `2480 + encoded_inner_bytes + 1 <= 2 MiB` for
all 18 conservative source heights. The inner bound includes its own eight-byte
magic, and the final byte supports C's trailing-data probe inside packet two.
There is no third runtime packet, cap increase or unrestricted splitting.

Packet construction uses fallible exact-capacity reservations before zeroing the
already reserved range. An unexpected actual capacity or encoding beyond the
pinned height bound refuses; it never enlarges storage or starts a retry. These
are requested-storage source bounds, not allocator/RSS or physical-fit evidence.

## Closed operation and destruction

After the identity checks, the actual retained verifier accepts the untouched
original proof. The action constructs both full packet buffers, serializes the
original proof into packet one's body, and writes the fixed local header.
Header validation compares all 46 public and 256 cap words plus height to the
actual originals before the sole bounded decode. The locally trusted codec and
A's fixed decoder limit cannot be selected by packet bytes.

The decoded proof is then verified by the same actual retained verifier using
the original public values. It is reencoded into packet two; the complete used
packet, including both outer header and inner magic, must be byte-identical to
packet one. The decoded object is destroyed before C's typed header probes use
packet two. C mutates no proof and leaves packet one immutable. Both full packet
buffers are destroyed before the action returns its fixed observations.

The consuming function then destroys the actual original root while all needed
original claims remain held. Its non-Copy/non-Clone RetainedRootTransportReport
contains measurements followed by A's complete owner and exposes only a checked
borrow of those measurements. No packet, decoded proof, key, verifier, root,
acceptance or runtime continuation escapes. Both reservations remain inside A's
owner through the final report's last use and destruction.

Returned errors destroy local decoded/packet payloads under the same live
original reservations. The future driver's separate caller claim must cover its
fixed returned error and final formatting after this private phase ends. There
is no catch/retry, and ordinary Rust destruction supplies no asynchronous,
unwind-path, physical engine teardown or process/GPU memory qualification.

## Diagnostics and evidence limits

Exactly two numerical positive checks are intended: original and decoded. C's
two positive header checks are reported separately from those verifier checks.
Its 629 typed outer syntax/equality refusals are also separate: 24 syntax, 46
public, 256 cap, one supported-height mismatch and 302 canonicality observations.
They are not cryptographic mutation rejections. Generic codec failures remain
unclassified and earn no negative or storage-only rejection credit.

The action interval starts immediately before the original numerical check and
ends after packet destruction. It excludes preissue, prior proving and final
root destruction. Individual codec/verifier/header intervals are local nested
measurements and must not be added as independent complete-workflow timings.

This source-only implementation supplies no actual-root execution evidence.
A's four admission tests and C's six header tests are separately authored
synthetic checks; only coordinator execution can qualify them. Even a future
successful action would establish one bound local in-memory root roundtrip,
not disk persistence, complete artifact acceptance, raw/interior proof mutation,
transaction context, complete RingCT workflow, performance or production
acceptance. Existing security, row, thread and resource limits remain unchanged.
