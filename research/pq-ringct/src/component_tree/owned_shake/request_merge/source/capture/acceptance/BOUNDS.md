# Source-authenticated original leaf acceptance

This opt-in source slice connects B052's original-registration cap provenance to
one actual consuming outer producer and its actual runtime retirement. It is a
prerequisite for authenticated children of the bounded parent compiler. It does
not implement that compiler, admit the complete request graph, or change B051's
`Result<Infallible, RefusedRequest>` complete-request refusal.

Before native work, the original `ParentSourceBound` preissues a leaf cap claim
and a separate `PreissuedLeafAcceptance`. The latter holds complete source and
caller/result/tuple/report storage plus an independent CPU verifier lifecycle.
That lifecycle is the maximum of all eighteen admitted heights, 8 through 2^20,
for the unchanged 46 public values and canonical 64-root/capacity profile. Every
height is inspected; no monotonicity or observed output size is assumed. Both
claims are additive to the existing output/key/verifier and producer claims and
must reduce the original first native PCS capacity before native dispatch.

The new closed producer accepts the original preissued continuation and source
acceptance owner. Before runtime startup it checks the actual compiler against
the exact original leaf source and request. During fresh registration, B052's
capture rechecks that source and pointer equality between the actual original
compiler Program and the RegisteredProgram's Program. It copies the actual
canonical cap into its original fixed claim. While that same immutable
registration is borrowed, `RegisteredProgram::verifier()` independently rebuilds
the CPU verifier from the actual registered cap. This separate verifier has its
own full preclaimed lifecycle in addition to the output's independently retained
key. It is not supplied by a proof, report, caller callback or output artifact.
The core private cap constructor is not exposed or called across crates.

The actual registration is consumed by the existing fresh GpuRequired backend.
Native receipt checks, output retention and initial independent verification are
unchanged. After all borrowed runtime/registration locals die, the same private
Session is actually retired even after a returned attempt failure. Only successful
production, positive bounded managed peak, zero managed/tree live bytes, released
lease and unchanged original ledger claims can construct `RetiredLeafAttempt`.
That type's fields and constructor are private to the fixed producer. It contains
the actual captured verifier, actual output and actual retired original owners
together. Numeric receipts, summaries, raw outputs and separately retired
owners cannot construct it.

The numerical source-acceptance entry consumes only this opaque attempt. It
checks exact request/ledger/cap claim/metadata ownership and matches output spec,
height, all public values, every cap root, cap length and capacity to the genuine
source-checked compiler/registration. The separately reconstructed verifier then
verifies the actual proof after retirement. Failure is terminal cleanup; no
accepted child, restore token, fallback or retry escapes. Output diagnostics mark
the source key authenticated only after this numerical verification. They never
serve as the constructor for the opaque accepted child.

On success the independent verifier/configuration backing is destroyed before
its original lifecycle claim releases. Only the metadata portion is retained.
The accepted leaf retains the original proof/key/report owner, original fixed
cap and original cap/metadata reservations. It retains the full original request
source through a borrow but no original compiler, Program or witness borrow.
This permits a later correlated compiler-workspace owner to retire that compiler;
it does not itself extract or restore compiler tokens. The returned companion
retirement remains opaque and owns the original startup/PCS/support claims.
Every payload precedes its reservation in destruction order. Cap and verifier
copies are charged independently, without Arc-sharing or move-elision credit.

The resource envelope remains managed8GiB, context4GiB, worker32GiB,
native24GiB, host trees inside worker, process47GiB, zero swap and unchanged
rows/threads. Pure authored tests cover all-height independent CPU admission,
exact/one-byte-short metadata/lifecycle claims, terminal token cleanup and every
source binding field/cap word. Those tests construct no registration, proof,
retirement or accepted child. No source was compiled, no test/planner/auditor or
GPU workload was run by B; only rustfmt parsing and source/hash inspection ran.

A genuine qualification requires the opaque all-native-to-outer bridge and an
exact source/emitted-binary/environment/device guard. B056 now source-implements
the first paired leaf through A040/A041, without qualifying its execution. Its
separate wrapper consumes only the dedicated producer-created retired attempt,
checks the original A/B owners, then calls the same private numerical acceptance
implementation. The shared helper's complete argument and return frames are
additional in every original acceptance claim. New native/outer/result owners
remain covered by the original independent B056 bridge claim. Parent source
compilation, authenticated parent outputs, correlated compiler reuse, retained
parent graph, transaction/final closure, artifact/mutation/terminal audits and
matched complete workflows remain outstanding. Source-local key authentication
does not authenticate the external transaction context, prove complete workflow
admission, or establish speedup/security adoption. Production PairedV1 stays off.
