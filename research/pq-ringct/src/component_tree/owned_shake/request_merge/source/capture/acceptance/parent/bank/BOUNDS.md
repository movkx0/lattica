# Private original compiler bank

B061 is a storage and reclamation prerequisite. The module is private to the
parent compiler subtree and has no reexport, dispatch method, raw reservation
getter, or constructor taking an existing compiled payload. It does not supply
same-attempt lineage, a successful full request, or a measured resource fit.

The bank borrows all five exact immutable leaf plans and the original parent
source bound. It validates the source/ledger, PairedV1 ordering, exact spans and
each retained leaf source identity. It admits a componentwise maximum, separately
for host and device bytes in every quota category, of the five complete leaf
requirements and the existing complete two-child parent compiler requirement.
It also admits a separate additive PhaseScratch caller requirement. Neither
admission enlarges the 32 GiB host or 8 GiB device worker allowances.

The caller census covers complete bank, banked compiler, compiler failure,
retaining verification, reservation split/reunite, exact A044 report reclamation,
source/group/parent storage, wrapper, iterator, result and return frames without
inlining or move-elision credit. It includes the existing parent caller census
because parent storage arithmetic may run before its compiler chunk is split.
The shared maintained leaf compiler gains one private verification hook and an
additive source-derived census for its new forwarding frames. Its default hook
keeps existing verification and release behavior. The private bank hook invokes
the actual ProducedHashx retaining verifier; no proof or receipt is fabricated.
Both paired verifier originals stay in separate fixed slots until compilation
finishes. The speculative single-verifier saving is not part of B061.

Compilation splits the original complete bank. The returned banked owner couples
the actual compiled payload to the residual originals and enclosing caller claim.
Default field destruction destroys the compiled payload before the bank. A leaf
payload guard clears its witness before destruction on ordinary return or unwind;
the existing parent Payload guard supplies the corresponding parent behavior.
All fallible reclamation identity/source/ledger/requirement checks happen through
borrows before destructuring either banked owner. An early refusal therefore
preserves the same payload-before-bank field destruction order.

Successful reclamation also requires the Program Arc to have exactly one strong
owner and zero weak owners. A surviving registration/verifier/program handle
therefore cannot make this bank return its compiler capacity while its backing
still exists. This check supplements the private sequence's required actual
retirement and borrow ordering; it does not replace that lifecycle evidence.
On terminal refusal or drop, every independently retained Program alias must
keep its own full backing charge. The future combined owner must establish that
those aliases either die at actual retirement or remain separately charged on
failure and unwind. This capsule creates no retained registration/verifier alias
and does not qualify such runtime/drop paths.

On successful leaf reclamation, the actual Program/public/witness payload is
destroyed first. A044 then checks the exact WrapperCompilation PhaseIdentity,
original ledger, original report requirements and preclaimed caller. It destroys
the actual report Box and encoding before returning that same original token.
Only then are program, input and report originals reunited with the residual bank.
For a parent, its actual witness-clearing Payload dies before its whole compiler
original reunites. Exact original totals are rechecked before returning a bank.
No released capacity is readmitted, no category is converted and no quota observer
receipt replaces original ownership. Every refusal is terminal; a failed report
still retains its own bounded claim until its actual payload is destroyed. A
compiler failure additionally retains the original bank caller claim in the same
error variant, after the report field, through its last reporting use.

The arithmetic tests distinguish category and memory-domain maxima, overflow and
unchanged quota peaks through original reunification. The ignored source test

checks exact bank admission, foreign worker/order refusal, missing native-child

It performs zero native or recursive proofs. These tests and the crate have not
been executed by Agent B; the coordinator must run normal/test builds, focused
tests and the exact source selector under the serialized guard. Changes in the
default compiler requirement require repeating first-leaf/source capacity checks.
