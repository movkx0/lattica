# Complete-request refusal preflight

The executable `request_merge.rs` is a source-only metadata owner, with no
runtime, proof, compiler, verification, or dispatch entry. Its success type
for `require_complete` is uninhabited. Even five genuine B050 group source
bounds cannot turn it into native or recursive dispatch authority. The
existing production PairedV1 refusal stays unchanged.

The fixed first scope is the active-policy HashX source: input 16,416 bytes,
output 137 bytes, and original native permutation counts
`[16,16,16,16,16,16,16,8,1,1]`. The constructor borrows A035's immutable admitted
request. It checks every original native first/count/height/width and derives
five consecutive pairs without splitting or substituting a segment. It uses
three fixed carry slots and four fixed parent slots to reproduce the existing
push/finish schedule. The final parent merges level 2 [0,120) with level 0
[120,122), producing spec level 3 [0,122). A spec level is scheduling metadata,
not a proved row count, recursive height bound, or acceptance receipt.

`RequestClosurePlan` consists only of an immutable request borrow and fixed
context; the enclosing worker charges its allocation-free initial planning
frame before construction. Before deriving the tree or retaining any source
metadata, `open` requires the exact source-derived `RegisteredMetadata`
reservation from the original ledger. A larger category claim, another
category, a foreign ledger, or a worker allowance above the unchanged 32 GiB
host / 8 GiB managed-device ceilings is refused. This module never selects or
changes the 4 GiB context reserve, native allowance, host-tree allowance,
thread/row/process cap or zero-swap guard. Its claim is inside the existing
worker allowance and must reduce any later native PCS capacity.

The metadata census uses `size_of` of all complete plan, admitted owner,
refusal, Result, source-bound, context, tree, carry, interval, report and
reservation representations, including input, return, moved and caller
copies. Explicit helper structs count source/tree iterators and scalar/identity
frames. The census's own array and slice iterator are counted separately;
there is no move-elision credit. This module allocates no String, Vec, Arc,
proof template or program. The reservation stays with the admitted owner and
each complete refusal; the source-bound array is destroyed before the
enclosing original metadata reservation. An incoming source-refusal owner
destroys its separate rejected source before the request owner. The final
refusal destroys its report before the request owner.

Each retained leaf source must be a genuine `GroupSourceBound` issued by the
existing source planner. `retain_source` requires the exact immutable request
pointer, original ledger, fixed endpoint context, PairedV1 layout, next ordinal
and exact precomputed span. `GroupSourceBound::is_for` additionally checks its
original retained metadata reservation, full source contract and fixed compiler
limits. All backing remains charged by that source's own original reservation;
the request claim accounts only for its enclosing storage and caller frames.
Invalid handoffs return complete original owners without changing ledger
counters or consuming an attempt. No compiler or native attempt exists here.

The refusal reports these distinct missing integration bounds:

- Original leaf source bounds, until all five have been retained.
- Parent registered-verifier source plus exact merge/public binding and caller
  census. Generic core shape planning exists; this composed source is missing.
- Independent parent CPU-verification storage and lifetimes.
- Correlated reusable compiler workspace, actual payload destruction and exact
  runtime/producer completion provenance.
- Every overlapping retained recursive key, proof, report and source owner.
- Complete consuming transaction and final-aggregation height/resource closure.

No caller-controlled Boolean, budget, numeric footprint, cap, proof header or
source count can discharge these blockers. Reports expose only scheduling
counts and missing-bound reasons. They report no generated proofs, timing,
GPU reuse, completion or speedup.

Five focused tests are authored for reference carry-tree equivalence,
asymmetric levels, coverage/order/overflow mutations, request/context/layout
identity, all wrong categories, exact byte boundaries, foreign ledgers,
enlarged allowances, refusal ownership and zero terminal quota. One separately
guarded ignored CPU source qualifier inspects five genuine B050 leaf sources,
checks wrong-order handoff preservation and duplicate rejection, and confirms
that complete leaf-source retention still cannot close the request. It makes
zero native or recursive proofs and authenticates no transaction context.

The coordinator alone runs tests/builds. Rustfmt parsing and capsule/whitespace
checks are not compilation, test or GPU evidence. The proposed future compiler
and parent lifecycle remain in `../request_workspace/LIFECYCLE.md` and
`RESOURCE_INTERFACE.md`; their names are not callable APIs in this capsule.
