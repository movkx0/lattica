# Original native-to-outer singleton continuation

This is an ignored component qualifier under the existing serialized Linux
x86_64 host-tree guard. It does not enable production transaction acceptance,
full-transaction PairedV1, N3/N4, final aggregation, or a throughput claim.
The native and outer proofs are freshly generated with GpuRequired execution.
The existing bounded compiler and public endpoint preprocessing run on CPU;
receipts explicitly record this boundary.

Before the first native attempt, the qualifier holds the original request,
source-shape metadata, compiler/program/input/verification/report claims, native
attachment metadata, outer P/K/V owners, two mutation-verification passes,
outer OpenCL wrappers, fixed reports, the existing planner reservation, and
additional source-envelope/continuation headers. It then constructs the native
host phase, which uses only the real remaining PCS budget. A029's read-only
capacity declaration completes all outer row/phase checks before native GPU
dispatch. A refused configuration cannot reach proof production.

The backend source plan is move-only and issued at the original idle boundary.
It captures every allowed row shape and immutable physical/runtime selection.
After native proving, A028 retires the real runtime and returns only the sealed
original startup, wrapper and PCS owner. The original metadata adapter attaches
the native proof without changing any ledger counter. Native proof verification
and compiler inputs remain separately owned through bounded compilation.

After compilation, the original request-bound source plan and actual GPU layout
must conform. The sealed restoration API reconstructs the pending outer runtime
from the original startup claim. The exact original PCS claim becomes the outer
backend scope, and the previous native wrapper claim remains live separately.
Startup managed bytes count inside the unchanged full 8 GiB phase ceiling.
No reservation, capacity increase, token recreation, retry or fallback occurs
after native dispatch. Attachment and outer binding compare full ledger
snapshots; only documented payload destruction releases later claims.

The actual existing consuming outer producer validates and emits its real
preprocessing and proof stage receipts, constructs the real key, independently
verifies the proof, and retires its runtime before phase claims are dropped.
The fixed recheck uses a separate claim issued before native proving, mutates
two public values in place without cloning a proof, requires rejection, restores
them, and requires acceptance. The terminal qualifier drops every original
owner and requires zero ledger current bytes. The coordinator must additionally
audit terminal GPU/process state and preserve all failed-run evidence.

Original report bounds cover the existing returned report and publication
payloads. Both the default and preissued constructors use the same checked
additive census for four producer move/forwarding slots, four returned output
result slots, validation views, request/report borrows, and concrete streaming
serializer, stderr, lock, formatting and error/result headers. Streaming goes
directly to stderr without an intermediate String or JSON Value. These headers
receive no overlap credit from the existing payload or 1 MiB planning claim.
The separate planning claim remains live through source queries, selection
capture and bounded core planner errors. Additional exact inline source plans,
move/result owners and continuation headers are separately charged. The fixed
fixture charges SHAKE XOF state, one-byte buffers, endpoint context, snapshots,
and the already audited scalar Poseidon constructor tables. No synthetic
Program or hint is evaluated as a bound.

This first closure supports one native segment and one recursive singleton.
Paired/odd-tail execution needs a separately source-closed native phase reuse
plan before the first native attempt. Cryptographic parameters, native
segmentation, AES, transcript semantics, row/thread limits, host/native/process
caps and zero-swap requirements are unchanged.

## Original outer retirement and restoration seam

B047 adds a separate consuming producer method that returns the independently
verified output together with a private-constructor, move-only owner of the
actual retired outer Session and its original startup, PCS, native wrappers,
outer wrappers, reports, planning and metadata claims. The runtime is retired
before an error is returned as well as before success; a failed proof cannot
mint this continuation owner. Its original complete current/peak ledger
snapshot must survive retirement unchanged. Existing default producer behavior
and the B046 exact qualifier are unchanged.

The next group's ReadyOuter must already have been source-closed before the
first native proof. finish_outer accepts only the same request and ledger,
layout and consecutive ordinal, segment span and permutation span. It checks
the declared exact original startup/PCS requirements and preissued next backend.
A032 restores only an actual sealed retired outer runtime whose sole binding
was captured at retirement. The original PCS/native wrappers move unchanged.
Binding the already-compiled next source must not change any ledger counter.
Only then are the previous group's obsolete outer support owners destroyed;
the exact expected current-byte category deltas and unchanged peaks are checked.
No source query, capacity enlargement, new reservation or fallback is admitted.
This seam is not wired to a paired request or production dispatcher.

The additive pre-native metadata census includes retired/continued output
owners and return moves, pending/runtime/restoration result owners, snapshots,
requirements, reservations, summaries, limits and formatting frames. It remains
separate from payload bounds, original startup census, fixed report publication
and the planning claim. The restored pending owner drops before the support
claims during both ordinary cleanup and the exact qualifier.

The new ignored qualifier uses the same singleton native/CPU compiler/outer
proof construction as B046, but consumes the actual outer retirement into
A032 pending startup restoration and then drops it. It performs no second
outer preflight or dispatch and emits restored_outer_dispatched=false. All
original startup/PCS and complete ledger counters are checked unchanged through
restoration; two independent public mutations are rejected and all current
quota reaches zero at the terminal boundary. The original B046 test remains a
separate exact selector. Coordinator source/executable, receipt, process/GPU,
zero-swap and terminal audits remain mandatory.

A complete pair/odd-tail request still needs a closed native-successor owner:
preissue every segment's source/output/verifier claim and every group's
compiler/P-K-V/wrapper/report/planning claim before the first GPU attempt;
move only sealed original startup/wrapper/PCS through the native successors;
refuse configurations that do not fit the unchanged original PCS budget.
The minimal supported research sequence would be two or three existing
singleton native segments, never resegmentation of an existing batch. Full
interior boundary authentication and request/final aggregation closure are
additional obligations. Neither this seam nor restore-only qualification
claims those operations or any complete-workflow improvement.
