B056 composes A040/A041 with the existing B050 source backend and B053 source
acceptance. It is a test-only component seam for PairedV1 Leaf0: the unchanged
native segments0 and1, each16 permutations, covering [0,32). It adds no complete
request, parent proof, transaction or final-aggregation dispatch. B051 remains
`Result<Infallible, RefusedRequest>`, and production defaults remain Singleton.

`FutureHashxLeaf::reserve_before_native` reserves every added B orchestration
owner, plus the existing FutureOuter output/wrapper/report/metadata/planning
claims, before A prepares native0 and fixes original PCS capacity. Independent
source acceptance must already be preissued from the complete original five-leaf
parent source. The first-leaf precheck requires the exact original source pointer,
request and ledger, cap and verifier claims, paired ordinal0 and complete span.
Source-identical descriptions cannot replace the original source allocation.

A's independent `with_outer_bridge` claim also precedes native preparation.
`complete_before_native` first calls A041 with B's exact request and ledger,
then derives the genuine backend from the actual A039 capacity. It moves only
that backend into A's opaque ticket and retains every original B claim. Neither
matching numeric capacity nor matching geometry can correlate a different
native request. The actual native call borrows the same ticket through all ten
fresh native proofs. There is no raw reservation adapter or legacy singleton
`RetiredNativeReservations` conversion.

All ten native children and attachments must move into their separately
preclaimed B owners before `finish_native` can consume A's ticket. B checks the
actual compiler against its exact original source and acceptance before binding
the unchanged Program/public/witness through A. Those compiler allocations are
borrowed until the actual outer attempt and source acceptance end; this seam
does not establish correlated reuse of a compiler workspace across five leaves.

The actual outer producer uses GpuRequired with no identity receipt hint or
proof cache. It captures an independent verifier only from the exact registered
Program, retains the existing full output verifier and proof claims, emits real
setup/proof reports, and independently verifies the output. Returned setup,
proving, report or output failures all consume `ActiveHashxOuter::finish` before
returning failure. A performs exact retirement and removes its backend's compiler
borrows. Successful output alone cannot manufacture the correlated attempt.

Only that private attempt reaches the new acceptance wrapper. It checks the same
opaque A originals and original B support claims, then shares B053's private
numerical acceptance implementation. Exact Spec/height/public/cap/capacity checks
and independent CPU verification are unchanged. The verifier payload dies before

output claims without compiler/Program/witness borrows; the separate completion
retains opaque A originals and all B support claims. It cannot restore a runtime

tuple, destructure and closure frame, plus separate helper arrays and bounded

and argument frames to every original acceptance claim. No inlining, move or
tail-call elimination is assumed, and no old larger PCS capacity may be reused.

extra-category refusal and full release. The existing serialized source qualifier

Coordinator builds and tests, genuine native-to-leaf execution, wrong native
