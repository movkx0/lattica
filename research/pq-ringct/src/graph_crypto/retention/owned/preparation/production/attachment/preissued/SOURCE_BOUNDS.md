# Preissued native singleton adapter

`PreparedNativeSingletonAttachment` is an opaque reexport of the existing
`MetadataOwner`; it introduces no new wrapper, payload or reservation category.
Its private fields retain the exact original request/index, immutable source key
and retention shape, and the original additive adapter reservation last. Existing
A023 source arithmetic already charges this type, source/pending/destination
owners, key and shape construction, error overlap and final verifier public Vec.

`source_requirement` performs only source planning. `reserve_before_native`
requires the original request ledger, constructs the same fixed singleton source
plan, issues its exact adapter reservation, then derives the key and shape under
that original claim. A full workflow can perform this for every child before its
first native proof, and its actual native PCS budget sees those retained claims.
The source remains one permutation and 4096-by-517; unsupported batches/indices
and insufficient memory are refused before native dispatch.

`attach` consumes that same owner together with an intact
`VerifiedNativeSingleton`, using the existing identity and proof-shape audit.
It admits no new reservation, reconstructs no token, allocates no new proof copy
and does not rebuild metadata. The original proof/report owner remains intact
inside the compiler child. Final numerical verification still uses a distinct
preissued original verifier claim. The A023 convenience conversion remains
unchanged for isolated component use; it does not become workflow admission.

Three CPU tests cover source-only requirements, exact original category charges
and move/destruction, original request/ledger/index identity, one-byte-short
admission and unsupported source shapes. The existing exact A024 host qualifier
is extended to reserve the adapter, mutation verifier and final verifier before
native preparation. It requires the full ledger snapshot to remain unchanged
across attachment, independently re-verifies the resulting compiler child, then
destroys all payloads before checking terminal zero current quota. The same
selector/environment and component-only timing scope are retained.

This API closes only the persistent adapter boundary. A complete graph still
requires source-derived compiler/output/report/verifier requirements and a closed
sequential phase-owner design that retains and transfers the original runtime
and managed scratch claims after exact retirement. Reserving two full managed
phases simultaneously or releasing one and inventing a new post-dispatch claim
does not satisfy that requirement. No full RingCT or performance claim is made.
