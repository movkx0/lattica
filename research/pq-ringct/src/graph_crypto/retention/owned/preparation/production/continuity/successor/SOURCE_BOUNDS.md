# Preissued native singleton successor

This source boundary supports only the already selected two- or three-segment
singleton SHAKE request. It changes neither native segmentation nor acceptance.
Every future source/preparation/proof/report/independent-verifier/bookkeeping
claim is reserved before the first native constructor derives its PCS budget.
Every ready successor is completed against that actual unattempted first owner,
not a copy of its reported capacity. The enclosing fixed sequence additionally
charges `additional_sequence_caller_host_bytes` before source construction.

Core preissue checks the actual unattempted host-profile phase, original PCS
claim, fixed 4096-row/517-column/216-public/42-periodic geometry, same input and
output lengths, exact future preparation/output/verifier owners and ledger.
The selected future must be one or two singleton steps after the first source.
No environment, physical-device lookup, dynamic source allocation, new plan or
reservation occurs at this point. The initial original PCS plan already covers
the same fixed rows, width, physical selection and operation-host allowance.
Per-segment recording/configuration/normalization remains under that segment's
complete original preparation claim and rechecks the actual geometry.

`RetiredNativeReservations` now retains the original immutable inline
`NativeShakePcsPlan` and completed preparation metadata. It still owns no live
runtime, device payload, configuration, witness, native proof or identity Weak.
The plan consists only of captured limits, a numeric footprint and Copy source
device census. Actual retirement destroys the old Weak before sealing these
owners. Existing native-to-outer extraction explicitly destroys the plan before
returning the same original startup/wrapper/PCS tokens; it does not add an
alternative constructor. The new native-successor path moves that exact plan
and those exact wrapper/PCS claims into the next phase without replanning or
readmission. No reservation is split, enlarged, released or replaced on success.

The native phase records whether its consuming producer actually returned a
successful owned proof. A failed attempt may still retire normally for cleanup,
but can never enter the successor restoration. A success creates no retry:
the next phase has fresh one-shot execution state and must use a preissued
different consecutive segment. Its new actual runtime issues its own Weak.
Private proof verification remains a separate research requirement.

The research `ReadyNativeSingleton` accepts only the private correlated
`VerifiedNativeSingletonWithOriginals` bundle. It checks the exact same immutable
request object, previous index plus one, original ledger, exact startup claim,
actual retirement receipt, live future preparation/verifier/bookkeeping owners
and source geometry before extracting anything. Core independently requires
the previous successful proof, exact zero-live/lease-released actual retirement,
the next consecutive geometry, original host-tree profile and exact original
PCS/wrapper requests. Missing, skipped, reordered or foreign inputs return both
complete input owners. No numeric receipt or raw Reservation mints authority.

Research first computes its exact restoration plan against the still-sealed
actual original startup. Core then either returns both untouched inputs or
moves that same startup into a separately unforgeable `SealedNativeStartup`.
A private infallible consumer accepts only that seal and constructs an unstarted
PendingRuntime using the already validated plan. This ordering leaves no
fallible operation after partial input transformation. It never fabricates a
RetiredRuntime and never routes through the outer-only restoration API.

All added owners have an explicit source census. Core original wrappers charge
four successor and startup-seal slots, four full issuance result/refusal slots,
four full restore success/refusal slots, original plan/preparation/geometry
moves and fixed scalar/ledger/requirement results. The producer's new result
forwarding adds two full owned-proof results. Enlarged retired-original owners
are automatically included by existing `size_of` census slots. Research startup
adds four complete restored-runtime/phase result or complete-refusal slots plus
seal, startup-plan, limit and requirement moves. Each source bookkeeping claim
adds four full future, ready, claimed-source, constructor/completion/successor
result and core-successor slots. Caller frames independently cover full optional
future/ready owners, constructor and completion results, four full successor
results, returned proof/phase pairs and both complete error tuples per future.
These are additive within existing allowances; no released phase is used to
enlarge the first PCS capacity. Every original resource limit is unchanged.

Five authored CPU tests cover exact successor/odd-tail geometry versus skipped,
reordered and changed descriptors, batch rejection, complete future claims,
unsupported source counts/indices, foreign ledgers and bounded full caller
frames. They are not runtime evidence. Actual successor success/refusal, preserved
full ledger snapshots, new fresh native receipts, independent CPU verification,
mutation checks and final zero owners still require coordinator-serialized GPU
qualification. Paired and odd-tail recursive closure belongs to B's separate
source-bound sequence. This capsule supplies no full RingCT/N3/N4, performance,
different-witness cache or cryptographic security qualification.
