# Exact HashX original scratch lifecycle

This is an isolated native research component. It preserves the active immutable
HashX input 16,416/output 137 partition: seven batch16 segments, one batch8, padding
singleton at 120 and squeezing singleton at 121. It does not change default singleton
production, SHAKE/AES semantics, randomness, native segmentation, parameters,
thread/row limits or transaction acceptance. It implements no prepared-public
artifact cache: each recording, configuration, trace and proof is fresh.

`PendingNativeHashx` source-validates the original ReservedShakeRequest, admits
complete caller/result/array/diagnostic bookkeeping, and preclaims all ten native
proof/report owners, ten retained-output identities, ten attachment metadata
owners, one exact preparation mixed-category claim and one 64 MiB independent
verifier claim. Every preparation Requirements value must equal the first
category by category. Attachment source key/shape construction occurs under its
own original claim before native startup or PCS capacity derivation. Array slots
are fixed; there are no growing result/proof/report vectors.

`prepare` adds the original outer_host_v1 startup including 8 GiB host-tree quota,
then derives the first native PCS assignment from the actual remaining worker
host space, capped at 24 GiB. It wraps that actual unattempted first phase in a private
core sequence allocation identity. All nine future PCS plans are preissued from
that phase's private captured RegisteredGpuLimits and exact original capacity.
Their geometry, physical selection, tree profile and complete footprint must fit
before the first proof can execute. A plan is not reconstructed during successor
restoration. The identity allocation and every clone/control-block/return owner
are included in the original request bookkeeping; no raw identity constructor,
phase extractor or retired-original extractor exists.

The actual native producer retains the preparation original through recording,
configuration, proof production and exact runtime retirement. Recording/config
borrows end before retirement. Runtime retirement always runs after a returned
native failure; uncertain cleanup preserves the existing abort/poison boundary.
Core's actual runtime binding proves the retirement belongs to that phase. The
private retired HashX owner additionally retains its real sequence identity.
Independent CPU verification then uses B049's retaining-original path. All
configuration/verifier temporaries and the caller's temporary public Vec die
before the original 64 MiB component moves into NativeSegmentCompletion. Failure
is terminal; no fallback, admission or retry token is returned.

Each source-preissued successor consumes that complete opaque completion. It
checks original request/index/ledger, exact consecutive permutation boundary,
identical complete preparation Requirements, successful retirement with zero
managed/tree live bytes and a released lease, positive managed peak within 8 GiB,
original category claims, same captured PCS capacity and the actual private
sequence identity. Equal metadata from another attempt is insufficient. Every
refusal before transfer returns the complete successor and completion owners.
The closed driver treats refusal as terminal. Only after successful core/runtime
restoration does it destroy the old source preparation plan and move the actual
original mixed-category reservation into the preissued next plan. Snapshots
must remain exactly unchanged through retirement extraction, verification and
successor moves. No reservation is released/re-admitted to simulate reuse.

All ten verified proof/report owners remain live through the native sequence.
The final completion is terminal: it retains original exhausted native/core,
preparation and verifier scratch with no continuation or raw-token accessor.
Ordered take_next_child consumes each original proof/report owner into its
preissued NativeSegmentChild attachment. Both complete owners are validated and
the proof capacity is audited before transfer. The existing compiler receives
ReservedNativeChild, never a supplied raw artifact or a verification summary.
Original output, report, retained identity and attachment claims survive every
move and drop after their respective payloads.

The new retaining child-verifier entry accepts only this new attachment kind.
It validates original request/source key/shape/proof backing and returns the
actual B049 verifier token only after all verifier/config/public payloads die.
Its exact B049 caller helper, complete validation/admission/Result/tuple frames,
public Vec and source-key helper/diagnostics are additive inside the attachment
claim. Failure drops its token and exposes no successor. Existing singleton and
fixture verification retain their original drop-on-return behavior.

Complete owning return/refusal/array frames are additive to source payloads.
New core and OpenCL helpers explicitly count HashX phase/retired/successor
owners, source PCS results, actual Session/start/preflight/core-borrow/retirement
results and restoration tuples; B049's caller helper is included separately.
Workspace and attachment census counts their own whole owners, wrapper Results,
source/output/admission values, hashes, public arrays, loops and diagnostics.
Eight source/caller/return/destructure slots are retained without move-elision,
inlining or observed-capacity credit. Fixed source errors are immediately mapped
to bounded enums; the native PCS planner diagnostic allowance remains separate.
The bookkeeping original is last in the sequence owner; emitted child owners
have independent original output/report/metadata claims and may outlive it.

Limits remain managed GPU 8 GiB, context 4 GiB, worker host 32 GiB, native 24 GiB,
host trees 8 GiB inside the worker, process 47 GiB, zero swap and existing threads/rows.
The coordinator's A036 source screen admitted all ten native geometries with
zero terminal claims. That screen did not include this complete workspace and
cannot substitute for recalculating its actual first native capacity.

Four pure research tests cover exact additive claims/one shared scratch pair,
foreign/default source and enlarged limits, exact/one-byte-short source budget,
and startup shortage before device preflight. Three core tests cover all exact
shapes including padding/squeezing, skipped/reordered/changed geometry and
allocation identity distinction. Two explicitly ignored GPU tests cover 20 fresh
native proofs across distinct input witnesses with original snapshots/retained
child verification, and one genuine retirement followed by a refused reordered
successor with complete-owner preservation and zero terminal claims. They require
LATTICA_OWNED_NATIVE_HASHX_SCRATCH_QUALIFICATION=1 and the coordinator's exact
immutable exclusive-device guard. Source authoring/rustfmt are the only A-side
validation; the coordinator alone builds/tests/executes.

This component provides no B compiler/recursive-parent/source-height/independent
parent-verifier/output/key/transaction/final closure. B051's complete-request
Result<Infallible,RefusedRequest> gate remains authoritative. No full request or
faithful RingCT candidate may dispatch from these native measurements alone.
Complete recursive workflow benchmarks, artifact/mutation audits, full terminal
audits and matched performance acceptance remain outstanding. No speedup claim
is made by this implementation.
