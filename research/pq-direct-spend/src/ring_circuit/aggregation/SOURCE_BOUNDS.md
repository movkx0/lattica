# Fixed direct-ring N3/N4 source and ownership contract

This default-disabled research implementation proves complete direct-ring
transactions, then proves their full registered verifiers in one final flat
aggregate. It changes no production acceptance API. `Selection` accepts only N3
or N4. Native segmentation, alternate transaction splitting and security/profile
escalation are not part of this construction. If this exact topology fails the
source geometry screen, an explicitly different fixed topology must be designed
and qualified before any proof is generated; the runtime does not retry.

## Public source and relation binding

`ExpectedBatch` owns separately supplied canonical statements, all using the same
expected context/setup seed. It rejects repeated statement bindings and every
duplicate serial across all two-input transactions before compilation/setup.
Its four canonical public words stream a domain-separated digest of the fixed
flat version, count, profile, context, setup, ordered child bindings and serials.

Every child remains the full `RingDirectV1` relation: the shared hidden choice
among ten candidate pairs, original ternary/lattice ownership/account/opening
equations, two inputs/two outputs, 52-bit values, integer balance and original
AES-derived serial relation. Candidate eligibility and ledger spent-state
authentication remain external research trust boundaries, not adoption claims.

`PublicSource` is private. Only independently reconstructed expected-public
compilation plus fresh registration creates its cap, descriptor and CPU verifier.
An artifact supplies none of those sources. The aggregate's four public wires
equal expected constants. Each child's four public values remain fresh unknown
`ProofInputs` wires and equal that child's expected constants. Each full child
verifier uses that independently registered trusted cap. This avoids applying a
cap-specialization theorem to arbitrary public-value arithmetic.

The core `source_program::fixed_batch` constructor uses private invalid bounded
proof templates only to derive the exact program. Those templates and synthetic
inputs are never evaluated or returned. The genuine compiler emits the same
instruction/input order with actual independently verified child proofs. Its
manifest, geometry, retained program capacity and construction peak must match
the independently reconstructed program before aggregate proving.

The opaque-cap core bound receives exactly N trusted child shapes. Additional
bindings add at most `8*(N+1)` scalar operations and `4*(N+1)` constant wires:
one Constant and one Equal for each root/child public, with no new witness values,
cubic operations or Poseidon operations. Constant interning only removes work.
Pack the combined classes once. Every real compiler rechecks the derived
operation, row, wire and input limits. An observed compiler peak is never an
admission allowance.

## Fixed resource envelope and overlapping owners

Limits remain 32 GiB worker host, 8 GiB managed GPU, 4 GiB GPU context, 24 GiB
native host, the external 47 GiB process ceiling and zero swap. Existing thread
and row ceilings remain required by the coordinator guard. Source/compiler
quotas are requested capacity bounds, not measured RSS or allocator overhead.

The leaf compiler keeps the existing `2g`/`16m` and `FusedTernaryRangesV1` profile.
The aggregate keeps 2 GiB program construction, 2^26 wires, 2^20 proof-input values
and 2^20 padded rows. Transport retains the original 64 MiB proof/decoder storage
and original approximately 2 MiB encoded proof limit, including canonical
re-encoding scratch. No automatic quota increase exists.

Before compilation, the private `Budget` subtracts all of the following from
the original worker:

- All actual expected-statement Vec/ring capacities and all native witness
  backing, retained until each witness's final compilation.
- N+1 complete maximum-height CPU verifier lifecycle envelopes, each already
  including its own proof allowance, plus N+1 separate 64 MiB proof slots. This
  deliberate over-count grants no reclamation or overlap credit.
- A 4 MiB enclosing caller sublimit. `caller_census` adds actual source,
  compiler, verifier, plan, admission, artifact, report, failure, Result/catch,
  native witness/statement and move frames; the original 1 MiB session and
  reconstruction caller charge remains additive. At most 16 phase reports
  survive. Each native report is source-bound by 128 observations, 16 component
  slots and 32 capability-stage entries. Report names are static strings;
  session JSON/errors retain the existing caller charge.

Only one compiled program/input owner is active at a time. An exact private
`RegisteredGpuLimits` captures the smaller remaining host partition once; each
active `RegisteredGpuMemoryPlan` admits that partition and rechecks its captured
execution selection before setup/proving. Session itself keeps the original
worker limits so its terminal receipt remains comparable. Actual CPU shapes are
checked against the reserved maximum-height envelope before setup.

Compilation admits the full builder/input/auxiliary construction source before
any allocation. Source planning additionally admits complete `PlanningStorage`
and fixed-batch helper frames before symbolic/template allocation. Input Vec
capacity is explicitly raised to the fixed leaf/aggregate limit under a prior
old-plus-new allocation bound; synthetic and real plans therefore cannot differ
because of witness Vec spare capacity. Host constraint evaluation admits the
program, two full leaf input buffers and one value for every maximum aggregate
wire. No child program is retained during another child's compilation.

## Sequential workflow and verification

1. Compile/check each genuine native relation, record its exact identity/shape,
   admit its GPU plan, and destroy that compiled owner. Native witnesses remain
   charged for subsequent final compilation. The source-derived full N-child
   bound must close before the first GPU setup.
2. Rebuild each expected child program independently, compare the exact
   identity, register it, retain only its public cap/CPU verifier and bounded
   observations, and retire all GPU/program/synthetic owners. These sessions
   perform public setup; they are never counted as proof generation.
3. Reconstruct/admit the exact aggregate program and its proving/independent
   registration plans. The CPU/codec/output lifetimes and a newly created disk
   destination are already admitted before the first child proof.
4. Recompile and freshly prove each whole child sequentially. Check registration
   cap/identity against its independent public source. After complete GPU
   retirement, verify on CPU with that source. Public preprocessing reuse is
   reported. Retain each actual child proof in its original reserved slot.
5. Compile/evaluate the genuine full aggregate, compare the preflight source
   identity, destroy every child proof/source owner, and freshly prove the root.
6. Encode the root into the existing bounded output capacity, write/sync through
   the pre-created file, destroy the original proof and encoded buffer, then
   read through the same file owner. Check file length before exact bounded
   allocation/read, reject trailing bytes, and canonically decode. The original
   and replacement proofs never overlap.
7. Independently rebuild all expected child sources again; no producer cap,
   program, geometry or report is accepted. Reconstruct/register the root,
   compare the artifact descriptor to that fresh expected identity, retire all
   GPU/source owners and verify numerically on CPU. Return a private
   `VerifiedAggregate` owning the artifact only after acceptance.

Every setup/prover session explicitly finishes or closes without completion on
failure. Panics in compiler/backend phases are caught, program/input owners drop
before retirement, queue/context cleanup is required, and cleanup failure stays
a failure. Completed phase receipts remain in bounded failure progress. A changed
physical device across sequential sessions is rejected with its terminal receipt.

Each child and root has four separately mutated public words, one mutated trace
opening, restoration and positive verification after restoration. Only typed
`RelationRejected` counts as a cryptographic negative. Allocation/configuration/
admission errors and panics never do. Context/public/manifest envelope rejections
are counted separately as structural failures. N3/N4 domains cannot be parsed
as one another, single-ring artifacts or one-child-outer artifacts.

## Complete-driver ownership and qualification

The exact ignored complete driver uses genuine fixtures 0–2 for N3 and 3–6 for
N4. They share context/setup and differ in keys, coins, selected pairs, serials
and values, not merely context. Timer boundaries encompass fixture creation,
repeated public/real compilation, all setups/proofs/CPU checks/mutations, disk
round trips and destruction of final proof, private witnesses and full reports.
N3's proof and report are destroyed before generating N4; only fixed scalar case
statistics survive. Failure files and partially written artifacts remain evidence.

General API callers must account for all their other retained owners inside the
enclosing original worker; an independently invoked API is not an extra 32 GiB
reservation. `VerifiedAggregate` owns a bounded proof after the workflow returns,
but carries no continuing process-wide reservation token. The guarded driver
avoids that overlap explicitly.

No measured N3/N4 aggregate result, protocol-redesign 2x gate, faithful RingCT
speedup or cryptographic adoption review is asserted by this source. The private
note profile remains the separate quadratic join-split construction, with no
conversion to the wallet's cubic/context-extended aggregation profile.
